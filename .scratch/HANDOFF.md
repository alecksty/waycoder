## 0. 目标（判断「做完没有」的基准）

把 VML 的调用约定统一成**一条**：全部实参右到左压栈、**调用方清栈**。

起因是一个真 bug：`Lib` 里的 `println_int` 等函数是**被调方清栈**
（`move R1 @13; add R13 #8; push R1; ret`），而 C 前端生成的调用点**也清一次**
（`add R13 #4`）⇒ **每次调用净 +4 字节**，SP 一路爬进调用方栈帧踩掉局部变量。
症状诡异：**同一个局部变量连续读两遍会得到不同的值**（实测 `0` 然后 `242`）。

完整方案与全部实测记录：**`docs/VML调用约定统一.md`**（已入库，327+ 行）。
那份文档是权威，本文只放「最容易忘的」。

### 调用约定判据

```bash
scripts/vml-abi-probe/run.sh            # 全部 6 条，约 1 秒/条
scripts/vml-abi-probe/run.sh p3 p5      # 按前缀挑
```

判据只有一条：**跑得完 = 通过**。
**刻意不看探针打印出来的数** —— 栈漂移踩的正是打印路径自己要用的栈，
实测出现过「掩码印出 0、紧接着的分支却走了失败那一支」。

| 探针 | 钉的是什么 |
|---|---|
| `p1_args_order` | 6 个实参形参位置不错位 |
| `p2_args_expr` | 表达式实参（历史寄存器覆盖伤） |
| `p3_local_after_lib` | **调库后局部必须一字未动**（漂移本体） |
| `p4_local_declared` | 同 p3，但声明了 `__stdcall`（对照） |
| `p5_array_after_lib` | **调库后数组下标仍算得对**（漂移本体） |
| `p6_arg_types` | `char`/`short`/`double` 混合实参 |

⚠ **写新探针要注意「敏感度」**：漂移是 **+4/次**，要爬到某个局部头上才踩得到。
「变量少 + 调用少」的写法**测不出来**（`p3`/`p5` 的第一版就是这么假绿的）。
现在它们都用「多个局部 + 至少 4~8 次库调用」。

## 5. 这一轮学到的、下次直接照用

### 「统一清栈」与「参数走不走寄存器」可以拆开

我一度把两件事捆在一起做，把 R0-R3 装载整个删掉，结果是 543 处内联汇编全断。
它们其实是两件事：

- **清栈** —— 真 bug，必须修。
- **参数走寄存器** —— 不是 bug，只是 `Lib` 里 543 处 `asm("SYSCALL #6")`
  依赖的一种形态。

现在保留一份 **R0-R3 镜像**：参数既按规范全部在栈上（清栈因此只剩一条规则），
也顺手复制进 R0-R3（给存量汇编用，**一行都不用改**）。
清栈那一侧的修复由「用本前端重生成 `Lib/`」自动完成 —— 新前端生成的尾声本来就是裸 `ret`。

⚠ 镜像必须**在所有实参求值完成之后**。表达式生成器用 R0/R1 做 push/pop 暂存，
早装必被后一个实参的求值冲掉（历史伤：`probe(p+3*k, q+3*k, 3*k)` 曾传出 R1=101 而非 113）。

### `${}` 的语义（要改 543 处时用得上）

实现在 `CCompiler/CodeGenerator.Statements.cs:68`：

- 按占位符出现顺序把变量载入 **R0、R1、R2…**，文本里换成 `R0`/`R1`/`R2`
- **但 `regIdx` 每条 `asm` 语句独立计数** ⇒ 拆成多条 `asm()` 时每条都载入 R0、
  后者覆盖前者（实测 `24 = 12+12`）。**一条 asm 里写多个占位符才拿到 R1/R2。**
- **只做载入，不做存回**；分隔指令**不能用 `;`**（那是 VML 注释，后半截被整段吃掉）

配方：`asm("SYSCALL #6")` → `asm("SYSCALL #6, ${val}")`，展开成
`move R0 [R12+12]; syscall #6`。**实测只改 2 个函数就能让判据 4/6 → 6/6。**

### 「上游重生成」比看上去小得多

`tools/GenLib` 自带一键全流程 `-A`（编译 + 模块包装 + 聚合 + 绑定）。
难的不是跑，是跑完之后本仓要接得住。
