# 编译与运行

## 最快的路子：命令行

```
vml run examples/c/tetris.c        # 源码 → 直接跑
vml run ~/main.vml                 # 文本汇编 → 跑
vml run ~/main.vmb                 # 字节码 → 跑（最快）
```

`vml run` **自动识别**扩展名，不用你操心走哪条路。

## 在文件页点点点

**文件** 页 → 点文件名 → 菜单里选：

- **VML 编译** → 生成下一级产物（`.c`→`.vml`，`.vml`→`.vmb`）
- **VML 运行** → 直接跑

产物会出现在**同一个目录**下，同名。同名文件已存在时会问「覆盖 / 重命名 / 取消」。

## 手机上编译要多久

- **C 语言最慢**：一份带标准库的程序，前端编译 + 链接**要一两分钟**（手机上真的是一分钟量级）
- Python / Lua / BASIC 这类脚本语言快得多（几秒）
- **`.vmb` 装载几乎瞬时** —— 所以同一个程序反复跑，先编成 `.vmb` 再跑最省时间

> 编译期间不要以为卡死了：输入框那格会显示 `⋯`，跑完提示符 `~>` 会回来。

## 编译卡住会不会出不来

不会。前端编译是同步的、**没有任何取消入口**，所以宿主加了一道**看门狗**：
180 秒还没编完就把控制权交还给你（那个编译线程本身没法中止，只是不让界面卡着）。

## 为什么 `.vml` 还能单独存在

- **能读**：它是文本，你能直接看到编译器生成的指令
- **能改**：手写汇编也是合法的（`vml test` 跑的就是一段内置汇编）
- **能当中间产物**：`.c` 编一次成 `.vml`，之后反复汇编成 `.vmb` 就不用再走前端了
