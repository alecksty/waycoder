# 从「编辑器」到「IDE」：差距清单

写于 v0.96.234（2026-09-19）。用两个独立调研把**四端**的编辑器现状摸了一遍
（移动端 `EditorPage` / 桌面 TUI `EditorScreen` / AvaLonia GUI `EditorWindow` / Web `app.js`），
下面每条都带**证据位置**与**能复用什么**，方便直接挑着做。

> 与 `docs/移动端编辑器待实现.md`（写于 v0.96.218）的关系：那份只讲移动端**编辑器内部**的 7 条；
> 这份把它划到「第二梯队」，并补上 IDE 真正缺的那几层（工程/工作区、代码智能、运行调试、
> 版本控制）。两份的 7 条状态**完全一致 —— 一条都没做**（中间十几版全在修主题/浮层/手势/编译器）。

---

## 0. 一句话结论

**四端都已经有一个"能编辑单个文件"的编辑器，而且移动端那个还相当完整**
（自绘虚拟化、语法高亮、IME/选区/撤销、编译+运行+错误面板、诊断气泡）。
但从 IDE 的角度看，**该有的三层基本是空的**：

| 层 | 现状 |
|---|---|
| **工程 / 工作区** | 没有多标签、编辑器内没有文件树、没有跨文件搜索。文件树在**另一个页**（`FilesPage`，而且是**逐目录的扁平列表**不是树） |
| **代码智能** | 没有补全、没有转到定义/查引用/悬停。`LspTool` 只支持 4 个只读操作、**只给智能体用**，任何编辑器 UI 都没接它 |
| **运行 / 调试** | 移动端有"编译+运行+输出面板"（两个 Tab：错误/输出），**没有终端**；四端都没有调试器；没有 git 集成 |

## 2. 差距清单（按"复用成本"排序，不是按"听起来重要"）

### 第一梯队 —— 引擎已经有了，只是没接上（**成本最低、体感最明显**）

| # | 缺口 | 为什么便宜 | 下手点 |
|---|---|---|---|
| 1 | **移动端「查找」补上「替换」** | `EditorCore` 里 **`ReplaceNext` / `ReplaceAll` / `FindOptions`（正则/大小写/全词）全都现成**，移动端 `BuildCoreForOutline()` 已经在用同一个 core 了 | `EditorPage.OnFindClicked`(:2819) / `FindLine`(:2843) 扩成"查找替换"面板；沿用 `TuiDialog.FindReplace` 的交互口径 |
| 2 | **移动端"保存时诊断"** | `DiagnosticManager.RunLintAsync(filePath)` **桌面 `EditorCore.cs:137` 在用，移动端一次都没调**；而 MAUI 的 csproj **已经把 `UI/TUI/Edit/**` 重新包含进来了**（`WayCoder.Maui.csproj:239`）⇒ 这个函数在手机上本来就能调 | `EditorPage` 的保存路径挂一次 `RunLintAsync` → `DiagnosticManager.Inject` → `RebuildBubbles()`。**渲染侧一行不用改**（气泡就是这么来的） |
| 3 | **自动缩进** | 一行逻辑 | `OnLineEditorCompleted`(:2764) 回车劈行时，把上一行的前导空白复制到新行 |
| 4 | **括号匹配高亮** | `CodeCanvasView.DrawCaret`(:1730) 那层已经知道光标在哪一列 | 加一次括号配对扫描（`EditorCore.MatchingBracketAt` 的思路可直接搬），配对的一对高亮 |
| 5 | **自动配对括号 / 引号** | 插入路径集中 | 插 `(`/`[`/`{`/`"`/`'` 时补另一半、光标停中间；⚠ **必须与 `FullWidthText` 全角转半角定下先后顺序**，别两处各改一次 |

### 第二梯队 —— 要动编辑器结构，但不动架构

| # | 缺口 | 说明 | 下手点 |
|---|---|---|---|
| 6 | **多标签 / 多文件** | 移动端现在 `_relPath/_doc/_editable/_history/_modified` 全是**单份字段** | `LoadAsync`(:641) 外面包一层"打开过的文件列表 + 当前索引"，把那一组状态**按文件**存 |
| 7 | **编辑器内的项目视图** | 现在文件树在 `FilesPage`（另一个 Tab），而且**是逐目录扁平列表、不是树** | 两条路：① 编辑器内加一个侧滑抽屉复用 `FilesPage` 的数据；② 把 `FilesPage` 自己升级成树（这一步对两个页都有用） |
| 8 | **上下文补全** | 现在辅助条是**手点字符板**（符号/运算符/关键字三张固定表 + 高频排序），不读光标上下文 | 候选来源现成：`Syntax.ForFile(path).Keywords` + 同文件标识符现扫；插入路径现成：`AssistInsertAsync`(:2189)；弹层可借 `ShowAssistPopup`(:2085)。⚠ 别在 `TextChanged` 回调栈里回写 `LineEditor.Text`（会打断 IME 组合态） |
| 9 | **代码折叠** | `CodeCanvasView` 零痕迹 | 要引入「行号 → 显示行号」映射，**渲染、光标、命中测试、选区四套都走这个映射** ⇒ 牵动面大，慎重 |
| 10 | **跨文件搜索** | 现在查找只扫当前文件 | 数据侧可以用 `FileWalker`（递归遍历的唯一实现）+ `FileIgnoreManager`（跳过规则唯一实现），别新写一套遍历 |

### 第三梯队 —— 需要新基础设施，别急着碰

| # | 缺口 | 为什么贵 |
|---|---|---|
| 11 | **转到定义 / 查引用 / 悬停** | `LspTool` 只有 4 个只读操作、且**只给智能体用**；VML 那 22 门前端**只有编译器、没有 LSP**。要么接真 LSP（手机上跑不起来），要么给前端编译器加一层统一的符号表（现在每个前端的 `symbolTable` 都是 `private` 且各写各的） |
| 12 | **调试（断点/单步/变量）** | 目标是自家 VM（`third_party/vml/VMLRuntime`），**理论上能加**，但那是 VM ↔ 宿主协议层面的事 |
| 13 | **git 集成（gutter / diff / 暂存）** | 移动端连 `GitRunner` 都被 csproj 排除了（`WayCoder.Maui.csproj:238`）；diff 渲染可复用 `UI/Shared/UnifiedDiff.cs`（跨端共享的纯逻辑） |
| 14 | **编辑器内终端** | 移动端有独立的「命令行」Tab（`ShellPage`），要不要合进编辑器是个产品决定 |

## 3. 建议的头三步（都是第一梯队，一天量级）

1. **移动端保存时诊断**（第 2 条）—— 引擎现成、渲染侧不用改，直接让"报错"从"要点运行"变成"保存就有"。
2. **移动端查找→查找替换**（第 1 条）—— `EditorCore` 里现成的，补一下面板；顺带把四端不一致的那条抹平一半。
3. **自动缩进 + 括号匹配高亮 + 自动配对**（第 3/4/5 条）—— 三条都是小改，但它们是"手感像不像 IDE"的主要来源。

做完这三步，「编辑器」与「IDE」的差距会从"三层都空"变成"只缺工程层与代码智能层"。

---

## 4. 需要你拍板的两件事

1. **范围**：只做移动端，还是四端一起对齐？（"四端不一致"那三条现在就在，越往后越贵）
2. **第 11 条走哪条路**：接真 LSP（手机跑不起来），还是给 VML 前端加统一符号表？
   这条决定了"补全/跳转"能做到什么程度 —— 只做**本文件内**的符号（便宜、能立刻做），
   还是**跨文件**（要工程模型，等于把第 6/7 条也一起做了）。
