# 模式体系：WayCoder 的四类模式（竞品对标版）

> 目标读者：用户 / 维护者 / 新贡献者
> 一句话：**确认轴管「何时打断」，边界轴管「能碰什么」，行为轴管「干什么活」，省钱轴管「花多少」。**
> 本版参考 Claude Code / OpenAI Codex / Crush / Aider 四大竞品的模式设计重新划分。

---

## 0. 竞品怎么做的（30 秒）

| 竞品 | 权限/模式设计 | 省钱设计 | 对 WayCoder 的启示 |
|---|---|---|---|
| **Claude Code** | **permission modes**（gate + behavior 合一）：`default / acceptEdits / plan / auto / dontAsk / bypassPermissions`。plan=只读规划；auto=classifier 模型审查（2026-08 起成新会话默认）；规则层 allow/ask/deny 叠加，deny 优先 | `/compact` 压缩 + 模型选择，**无删工具** | 一个 mode 同时管「哪些工具通过 + 行为提示词」；plan 就是「只读 + 规划行为」 |
| **OpenAI Codex** | **双轴正交**：`sandbox_mode`（物理边界：read-only / workspace-write / danger-full-access）× `approval_policy`（过程边界：untrusted / on-request / never）。`--full-auto` = workspace-write + on-request；`--yolo` = 无沙箱 + 无确认 | 无删工具 | **沙箱与确认完全解耦**——「能碰什么」和「何时打断」是两个独立开关 |
| **Crush**（WayCoder 对标） | ask / yolo 两档 + allowlist；TUI 内 Ctrl+P 切换模型 | 大小模型分工（`--small-model`：弱模型干摘要/提交，强模型干硬活） | 省钱靠**模型分工**，模式保持极简 |
| **Aider** | `/add` `/drop` 手动管理上下文；auto-commit + 弱模型生成提交信息 | `--weak-model` + repo map 压缩 + compact diff + prompt caching | 省钱 = 模型选择 + 上下文压缩 + 提示词精简，**绝对不删工具** |

**竞品共识**：没有任何主流编码 Agent 靠「精简工具数量」省钱。省钱的正道是——模型选择（小模型干琐事）、上下文压缩、提示词精简、输出上限。WayCoder 的经济模式含「删工具」属于**偏离共识的特色取舍**（见 §6-P1-②）。

## 1. 四正交维度总览（30 秒）

对齐 Codex 双轴 + Claude mode 语义，WayCoder 的模式应归为**四个正交维度**：

| 维度 | 决定什么 | WayCoder 映射 | 竞品参照 | 运行时入口 |
|---|---|---|---|---|
| **确认轴** approval | 「危险操作执行前**何时打断**」 | 权限模式 Ask(必问) / Auto(改必问) / SmartAuto(危必问) / Yolo(不问) | Codex `approval_policy`、Claude permission modes | Ctrl+P · `/permit` |
| **边界轴** sandbox | 「**能碰什么**」（可写范围 / 网络 / 系统） | 沙箱 SandboxMode off / project / network-off / hard | Codex `sandbox_mode` | `/perm` |
| **行为轴** mode | 「**干什么活 + 工具集**」（schema 层 + 行为提示词） | 工作模式 Build(建造) / Plan(规划) / Chat(聊天) | Claude `plan` mode（只读规划） | Shift+Tab · `/mode` |
| **省钱轴** economy | 「**花多少 token**」（提示词档位 + 压缩阈值 + 输出上限） | 经济模式 Off / Auto / On / Extreme | Aider / Crush（模型选择 + 压缩） | Ctrl+E · `/config economy` |

**纯聊天 = 行为轴工作模式 Chat**：不再是权限枚举，而是工作模式——0 工具 + 0 系统提示词（每轮只剩 user/assistant 消息），`--permit tiny/chat`、`/permit tiny` 路由到它。v0.82 时代的「确认·TINY」已并入，从确认轴彻底移除。

**现状差距**：边界轴与确认轴已按 Codex 双轴正交解耦（见 §6-P0-2）；省钱轴删工具是用户既定特色（见 §6-P1-⑤）。

## 2. 职责边界表（2 分钟）

| 维度 | 归它管 | 明确不归它管 | 现状违规点 |
|---|---|---|---|
| **确认轴**（权限模式） | Ask/Auto/SmartAuto/Yolo 四档确认策略；Auto=改必问（≈Ask，只确认写操作）；SmartAuto 三级分类 + 连续拒绝退回 Ask；SmartAuto Cautious 会话记忆（AutoAllowed） | **工具有没有**；**物理边界**；提示词 | YOLO 在 Build 下换 YoloToolAllowList（`Agent.Tools.cs`）——工具集仍受确认轴影响，属残留耦合 |
| **边界轴**（沙箱） | 可写范围（cwd/临时目录）、网络开关、越界批准、系统级隔离 | **要不要确认**（不联动权限）；工具集 | 已解耦：`SandboxManager.SetLevel` 只改边界；确认轴独立 |
| **行为轴**（工作模式） | Build/Plan/Chat 工具集（schema 层）+ 模式提示词 + 计划审批门 + 运行时拦截 | **要不要确认**；**省不省 token** | 无（三档职责清晰；Plan 只读白名单在 schema 层硬过滤） |
| **省钱轴**（经济模式） | 提示词档位（`SystemPrompt.cs:24-28`）+ 压缩阈值 + 输出上限 | 行为轴 Chat/Plan 的工具集（只读白名单不受经济精简影响） | `TrimToolsForEconomy` 在 Build 下删工具（`Agent.Tools.cs:330-339`）= 用户既定特色，仅限 Build 档 |

## 3. 单一决策链（谁优先）

核心原则：**每个问题只有一个回答者。**

| 决策问题 | 谁决定 | 决策顺序 / 优先级 |
|---|---|---|
| **工具有没有**（静态 schema） | 行为轴（工作模式）+ 显式白名单 + 黑名单 | ①工作模式（Chat=0 / Plan=只读白名单 / Build=白名单或经济精简）→ ②黑名单 → ③默认全量 |
| **能不能碰**（物理边界） | 边界轴（沙箱） | read-only > workspace-write > danger-full-access（越界需批准） |
| **要不要确认**（运行时） | 确认轴（权限模式） | Ask ≈ Auto（改必问） > SmartAuto（危必问） > Yolo（不问） |
| **省多少 token** | 省钱轴（经济模式） | Off > Auto > On > Extreme（提示词档位 + 压缩 + 输出上限） |

**提示词怎么拼**（Agent 构造/`ReapplyToolFilter` 按**工作模式**选择）：
```
Chat 工作模式 → 空串，且不注入 system 消息（纯聊天，每轮只剩 user/assistant）
Plan 工作模式 → GeneratePlan（只读分析精简版，~460 字符）
Build 工作模式 → 按省钱档位：
  --tiny 窗口  → GenerateTiny（极简 8 条）
  economy Extreme → GenerateExtreme（~265 字符）
  economy On   → GenerateEconomy（砍 RepoMap/Git/记忆/流水线）
  Off / Auto   → Generate（完整 15 区块）
```

**FilterTools 决策链**（`Agent.Tools.cs`）：
```
FilterTools（高 → 低）：
1. 行为轴 Chat    → return []（0 工具）
2. 行为轴 Plan    → PlanReadOnlyTools 只读白名单 ∩ PlanToolAllowList(仅可收窄) ∩ DisabledTools
                    bash 含于白名单，运行时按 BashGuard.IsSafeReadOnly 门控只读命令
3. 行为轴 Build   → 显式白名单（BuildToolAllowList；YOLO 覆盖 YoloToolAllowList）
    白名单非空     → 按白名单过滤
    否则          → 省钱轴精简 TrimToolsForEconomy（Build 档）
4. 黑名单 DisabledTools → 最后剔除
```

## 4. 入口对照表

| 维度 | 值 | 运行时切换入口 | CLI 启动入口 | 持久化 |
|---|---|---|---|---|
| **确认** | Ask(必问)/Auto(改必问)/SmartAuto(危必问)/Yolo(不问) | Ctrl+P · `/permit` · `/auto` · Web `/perm` | `--permit <mode>` · `--yolo` | 不持久（默认 Ask） |
| **边界** | off/project/network-off/hard | `/perm` | `--permission-mode` | config.json（SandboxMode；旧 suggest/auto-edit/full-auto 为兼容别名） |
| **行为** | Build/Plan/Chat | Shift+Tab / Ctrl+K · `/mode` | `--permit tiny/chat`（→Chat 工作模式） | 不持久（默认 Build） |
| **省钱** | Off/Auto/On/Extreme | Ctrl+E · `/config economy` | `--economy [on\|auto\|off\|extreme]` · `WAYCODER_ECONOMY` | config.json |

> 快捷键两层语义：无弹窗时 Ctrl+P=权限循环 / Ctrl+E=经济循环（`Program.Repl.cs:453-476`）；弹窗冒泡时 Ctrl+P=提示栏 / Ctrl+E=编辑器（`ChatScreen.Input.cs:663-698`）。

## 5. 命名对照表（消除同名异义）

| 现在的名字 | 属于哪轴 | 真正含义 | 文档限定词 | 长期建议 |
|---|---|---|---|---|
| `Chat` / `tiny` | 行为轴 | 纯聊天工作模式：0 工具 + 0 提示词（v0.82 的确认·TINY 并入） | **行为·Chat** | 保持；`--permit tiny/chat` 路由到它 |
| `--tiny` | 资源维度 | 小窗口 + 精简提示词，工具仍全量 | **窗口·Tiny** | 不动 |
| `Auto` | 确认轴 | 改必问：只读放行，危险/修改操作逐次确认（≈Ask，无会话记忆） | **确认·Auto** | 保持 |
| `Auto` | 省钱轴 | 按任务复杂度动态调节压缩阈值 | **省钱·Auto** | 保持 |
| `SmartAuto` | 确认轴 | 危必问：三级智能分级（Safe/Cautious/Dangerous） | **确认·Smart** | 保持 |
| `auto-edit` | 边界轴 | 沙箱：文件编辑自动、bash 需批准 | **边界·auto-edit** | 保持 |

**Auto 四义汇总**：`确认·Auto` / `确认·Smart`（/auto 命令）/ `省钱·Auto` / `边界·auto-edit` — 含义各不相同，对话中必须带轴前缀。行为·Auto 已随 v0.83 删除。

## 7. 与其它系统的交互

- **一次性模式**（`-p` / `--yolo` / 管道）：非交互自动放行，等价「确认=Yolo + 边界=全开」组合；`-p --permit tiny/chat` 一次性纯聊天
- **多槽位**（F1-F10）：确认轴全局共享、行为轴槽位级（`Agent.cs:91`）、边界/省钱轴全局 config；每槽位可独立停在 Chat/Plan/Build
- **子 Agent**：工具 = 父工具 − `SubAgentDeniedTools`（`ToolRegistry.cs:85-113`）− 全局白名单/精简/黑名单；子 Agent 默认 Build，不继承父的 Plan/Chat
- **窗口 Tiny**（`--tiny`）：独立资源维度，与经济在提示词档位上有重叠；与 `--permit tiny`（→Chat 工作模式）同名不同义，留意区分
