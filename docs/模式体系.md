# 模式体系：三分钟看懂 WayCoder 的三类模式

> 目标读者：用户 / 维护者 / 新贡献者
> 一句话：**权限模式管「要不要确认」，工作模式管「工具有没有 + 干什么活」，经济模式管「省多少 token」。三者正交，各管一件事。**

---

## 1. 总览：三张卡（30 秒）

| 维度 | 一句话职责 | 取值 | 运行时入口 | 当前代码位置 |
|---|---|---|---|---|
| **权限模式** PermissionMode | 决定「危险操作执行前**要不要确认**」 | Ask / Auto / SmartAuto / Yolo（TINY=纯聊天） | Ctrl+P · `/permit` · `/auto` | `Skills/PermissionManager.cs:20` |
| **工作模式** WorkMode | 决定「当前 Agent **能干什么活**（工具集 + 干活模式 + 计划审批）」 | Build / Plan / Review / Auto | Shift+Tab · `/mode` | `Agent/WorkModeManager.cs:12` |
| **经济模式** EconomyMode | 决定「**省多少 token**（提示词档位 + 压缩阈值 + 输出上限）」 | Off / Auto / On / Extreme | Ctrl+E · `/config economy` | `Config/Config.cs:42` |
| （附）**窗口 Tiny** | 独立资源维度：小窗口 + 极简提示词（**不是**权限 TINY） | 开关 + 窗口大小 | `--tiny [8k]` | `Config/Config.cs:272`、`Agent/SystemPrompt.cs:26` |

> ⚠️ 权限、工作、经济里的 **Auto** 是三个不同概念；权限 **TINY** 与窗口 **--tiny** 是两个不同概念。详见第 5 节命名对照表。

---

## 2. 职责边界表（2 分钟）

| 维度 | 归它管 | 明确不归它管 | 现状违规点（越界处） |
|---|---|---|---|
| **权限模式** | Ask/Auto/SmartAuto/Yolo 四档确认策略；Auto 的会话内记忆（AutoAllowed）；SmartAuto 三级分类（Safe/Cautious/Dangerous）+ 连续拒绝退回 Ask | **工具有没有**（不该禁工具、不该换白名单）；提示词；窗口；压缩 | TINY 禁全部工具 + 清空提示词（`Agent.Tools.cs:350`、`Agent.cs:157`）；YOLO 换 YoloToolAllowList（`Agent.Tools.cs:356`） |
| **工作模式** | Build/Plan/Review 的工具集（schema 层 AllowList）；模式提示词（Plan/Review）；计划审批门；运行时 BlockedTools 安全兜底 | **要不要确认**（不碰权限模式）；**省不省 token**（不碰经济） | WorkMode.Auto 的提示词声称 SmartAuto 分级，但实际不切权限模式（`WorkModeManager.cs:136-143` vs `ModeCommand.cs:30`） |
| **经济模式** | Off/Auto/On/Extreme 的提示词档位（`SystemPrompt.cs:27-28`）；压缩阈值（EconomySnip/Summarize/CollapseRatio）；输出上限 EconomyMaxTokens | **工具有没有**（不该偷偷删工具）；**要不要确认** | `TrimToolsForEconomy` 在 FilterTools 里直接删工具（`Agent.Tools.cs:330-339`），越界了「省 token」的本意 |

## 3. 单一决策链（谁优先）

核心原则：**「工具有没有」「要不要确认」「省多少 token」三个问题，每个只有一个回答者。**

| 决策问题 | 谁决定 | 决策顺序 / 优先级 | 当前实现 |
|---|---|---|---|
| **工具有没有**（静态 schema 过滤） | **工作模式 + 显式白名单 + 黑名单** | ①显式白名单 → ②工作模式 AllowList（Build/Plan/Review）→ ③黑名单 → ④默认全量 | 被 3 维度 5 层叠加：TINY 全禁 → WorkMode 白名单 → YOLO 白名单 → 经济精简 → 黑名单（`Agent.Tools.cs:345-382`） |
| **要不要确认**（运行时） | **只有权限模式** | Ask > Auto > SmartAuto > Yolo | `PermissionManager.CheckAsync`（`PermissionManager.cs:62`） |
| **省多少 token** | **只有经济模式** | Off > Auto > On > Extreme（提示词档位 + 压缩阈值 + 输出上限） | 提示词/压缩/输出正确；但额外越界删工具 |

**提示词怎么拼**（档位优先级，`SystemPrompt.cs:24-28`）：
```
TINY 权限 → 空（纯聊天，Agent.cs:157 直接置空，不调 Generate）
--tiny 窗口 → GenerateTiny（极简 8 条）
economy Extreme → GenerateExtreme（~265 字符，仅工具名 + 5 条核心规则）
economy On → GenerateEconomy（砍 RepoMap/Git/记忆/流水线，保留工具描述）
默认 → Generate（完整 15 区块）
```

**叠加时谁优先**（现状总表，`Agent.Tools.cs:345-382`）：
```
FilterTools 顺序（高 → 低）：
1. 权限 TINY           → return []（全部禁用）
2. 工作模式 Plan       → 用 PlanToolAllowList；否则 BuildToolAllowList
3. 权限 YOLO           → 覆盖用 YoloToolAllowList（空 = 回落下一步）
4. 白名单非空          → 按白名单过滤（跳过经济精简）
   否则                → 经济精简 TrimToolsForEconomy（Off=全量 / Auto / On / Extreme）
5. 黑名单 DisabledTools → 最后剔除
```

## 4. 入口对照表

| 维度 | 值 | 运行时切换入口 | CLI 启动入口 | 持久化 | 生效时机（现状） |
|---|---|---|---|---|---|
| **权限** | Ask/Auto/SmartAuto/Yolo/TINY | Ctrl+P · `/permit` · `/auto` · Web `/perm` | `--permit <mode>` · `--permission-mode bypassPermissions` · `--yolo` | 不持久（每次默认 Ask） | YOLO 确认即时生效；TINY 禁工具/清提示词需重建 Agent |
| **工作** | Build/Plan/Review/Auto | Shift+Tab / Ctrl+K · `/mode` | 无（默认 Build） | 不持久 | 工具集仅 Shift+Tab 即时刷新；`/mode`、计划审批门不刷新 |
| **经济** | Off/Auto/On/Extreme | Ctrl+E · `/config economy` | `--economy [on\|auto\|off\|extreme]` · `WAYCODER_ECONOMY` | config.json | 提示词/工具精简仅重建 Agent 或 Shift+Tab 生效；Ctrl+E 不持久化 |
| **窗口** | Tiny 开关 + 窗口大小 | — | `--tiny [8k]` | config.json | 启动时生效 |

> 快捷键有两层：无弹窗时 Ctrl+P=权限循环 / Ctrl+E=经济循环（`Program.Repl.cs:453-476`）；弹窗打开冒泡到 ChatScreen 时 Ctrl+P=提示栏 / Ctrl+E=编辑器（`ChatScreen.Input.cs:663-698`）。

## 5. 命名对照表（消除同名异义）

| 现在的名字 | 出现在哪 | 真正含义 | 文档限定词（现在就用） | 长期改名建议 |
|---|---|---|---|---|
| `TINY` | `PermissionManager.cs:20` | 权限=**纯聊天**：禁所有工具 + 清空系统提示词 | **权限·TINY（纯聊天）** | 改名 `Chat` / 纯聊天，`tiny` 保留别名 |
| `--tiny` | `Config.cs:272` | **窗口**=小窗口 + 精简提示词，工具仍全量 | **窗口·Tiny** | 保持不动 |
| `Auto` | `WorkModeManager.cs:12` | 工作=提示词声称 SmartAuto 分级但**实际不切权限**（名不副实） | **工作·Auto** | 删除，或联动 SmartAuto 权限 |
| `Auto` | `PermissionManager.cs:20` | 权限=首次确认后会话内自动允许 | **权限·Auto** | 保持 |
| `SmartAuto` | `PermissionManager.cs:20`、`/auto` | 权限=三级智能分级（Safe/Cautious/Dangerous） | **权限·Smart** | 保持 |
| `Auto` | `Config.cs:42` | 经济=按任务复杂度动态调节压缩阈值 | **经济·Auto** | 保持 |
| `auto-edit` | `SandboxManager.cs:11` | 沙箱级别：文件编辑自动、bash 需确认（`/perm`） | **沙箱·auto-edit** | 保持 |

**Auto 五义汇总**：`工作·Auto` / `权限·Auto` / `权限·Smart`（/auto 命令，注意是 SmartAuto）/ `经济·Auto` / `沙箱·auto-edit` —— 含义各不相同，文档与对话中必须带维度前缀。

## 6. 已知问题清单（本次不修，仅标注）

### P0（行为错误 / 安全边界）

1. **`ReapplyToolFilter` 只在 Shift+Tab 触发，其余模式入口都不刷新工具集/提示词**
   - 位置：唯一调用点 `Program.Repl.cs:406`；定义 `Agent.cs:177`；`/mode`（`ModeCommand.cs:36-46`）、`/permit`（`PermitCommand.cs:19`）、Ctrl+P（`Program.Repl.cs:454`）、Ctrl+E（`Program.Repl.cs:463`）、Web `/perm`、计划审批门（`Agent.cs:411`）均不调用
   - 影响：Ctrl+P 切 TINY 不实际禁工具/清提示词；Ctrl+E 切 Extreme 不精简工具；`/mode plan` 不应用 Plan 白名单——状态栏显示新值但 Agent 行为不变（显示与实际脱节）
   - 建议：建 `ModeCoordinator`，所有模式入口统一走「设置值 → 重算工具集 → 重算提示词」

2. **YOLO「上帝模式」受经济精简暗中裁剪**
   - 位置：`Agent.Tools.cs:356-373`，YoloToolAllowList 默认空 → 回落经济精简 → economy Extreme 时只剩 7 个核心工具
   - 影响：YOLO 语义「全部放行」被「工具没几个」暗中破坏
   - 建议：YOLO 只影响确认；若保留 YOLO 换工具集，必须显式跳过经济精简

3. **WorkMode.Auto 名不副实**
   - 位置：`WorkModeManager.cs:136-143`（提示词声称 SmartAuto 分级）；`ModeCommand.cs:30`（`/mode auto` 只改 WorkMode 不切权限）
   - 影响：提示词对模型撒谎——模型以为自动放行，实际权限仍 Ask 每次弹框
   - 建议：`/mode auto` 联动 `PermissionManager.SetMode("smartauto")`，或删除 `WorkMode.Auto`

4. **`--permission-mode` 的 `plan` / `acceptEdits` 被静默忽略**
   - 位置：`Program.cs:151-153` 只处理 `bypassPermissions`→yolo
   - 影响：Claude Code 用户传 `--permission-mode plan` 期望计划模式，实际静默跑 Build 全工具
   - 建议：`plan`→WorkMode.Plan；`acceptEdits`→沙箱 auto-edit；未知值给警告

### P1（职责纠缠 / 资源浪费）

5. **工具集被 3 个维度 5 层叠加控制（无单一决策链）** —— 见第 3 节；影响：行为难预测、安全审计困难
6. **WorkMode 双通道不对称：Review 只有运行时拦截，无 schema 层过滤**
   - 位置：`Agent.Tools.cs:355`（Review 走 `BuildToolAllowList`）；`WorkModeManager.cs:52-57`（`ReviewBlockedTools` 运行时拦截）
   - 影响：Review 下 LLM 看到写工具的 schema 但调用即被拒——浪费 schema token + 反复试错
   - 建议：Review 复用只读工具集的 schema 层过滤（与 Plan 同构）
7. **危险工具数据集分散且不一致**（5 处以上）：
   - `PermissionManager.cs:39-41`（DangerousTools）、`AutoModeClassifier.cs`（Safe/Cautious/Dangerous 三级）、`WorkModeManager.cs:44-57`（Plan/Review BlockedTools）、`BashTool.cs:42`（DangerousPatterns）、`BashGuard.cs`、`SandboxManager.cs:64-79`（SandboxBlocked）
   - 不一致实例：`test` 只在权限危险清单；`git` 只在 classifier/Plan 清单；`cd` 只在经济冗余集；`agent` 在 Plan 禁但 Review 不禁
   - 建议：统一 `ToolSafetyRegistry`（读/写/执行/危险/禁止分级），各模式从单一数据源派生
8. **`AllowedTools` 配置是死代码** —— `Config.cs:170`、`Program.cs:252-254` 有定义，但 `FilterTools` 从不读取；`--allowedTools` / `WAYCODER_ALLOWED_TOOLS` 写入后不生效
   - 建议：接入单一决策链作为最高优先级显式白名单，或标注 deprecated

### P2（一致性与文档）

9. **计划审批门批准后未刷新工具集** —— `Agent.cs:407-422` 批准后 `WorkMode = Build` 但不 `ReapplyToolFilter`；配置了 Plan 白名单时批准后执行阶段缺工具
10. **Ctrl+E 经济模式不持久化** —— `Program.Repl.cs:463-476` 只改内存值，重启回默认 Off
11. **TINY 同名不同义**（权限 TINY vs 窗口 --tiny）—— 见第 5 节
12. **Ctrl+P/E 双焦点语义不同** —— 权限模式是**全局静态**（多槽位共享），工作模式是**槽位实例**（`Agent.cs:91`）；多槽位并行时 Ctrl+P 影响所有槽位、Shift+Tab 只影响当前槽位

## 7. 与其它系统的交互

- **沙箱 SandboxManager**（`Infra/SandboxManager.cs:343-372`）：级别 `suggest / auto-edit / full-auto` 会联动权限模式（suggest→Ask、auto-edit→Auto、full-auto→Yolo）；反向 `/permit` 不联动沙箱。两套状态可能不一致
- **一次性模式**（`-p` / `--yolo` / 管道输入）：非交互自动 YOLO，跳过确认
- **多槽位**（F1-F10）：权限模式全局共享、工作模式槽位级（`Agent.cs:91` `WorkMode` 实例字段）、经济模式全局 config
- **子 Agent**：工具 = 父工具 − `SubAgentDeniedTools`（`ToolRegistry.cs:85-113`）− 全局白名单/精简/黑名单；子 Agent 默认 Build 模式，不继承父的 Plan/Review 只读约束
