## 2. 优势（源码支撑）

### 2.1 功能广度——单二进制覆盖最全
- **44 个工具**远超多数竞品默认集。除常规文件/Git/搜索外，内置：
  - **多模态 I/O**：`DrawTool`(文本 DSL→SVG/PNG)、`ScreenshotTool`+`ViewImageTool`、`TranscribeAudioTool`(语音转录)——Claude Code/Codex 无开箱即用的绘图与转录工具。
  - **MCP 客户端** `McpClient.cs` + `McpCache.cs`：可与任意 MCP 服务器对接，弥补自身生态不足。
  - **自研文档解析** `PdfExtractor/OfficeExtractor/CfbParser`：直接读 PDF/docx/xlsx/ppt，无需外部依赖。
- **多前端**：终端 TUI + `WayCoder.Gui`(Avalonia) + `WayCoder.Preview`(WPF) + `--json` 输出。TUI 是自研 40+ 文件控件库（非简单 ANSI），有真实交互控件、对话框、命令面板、懒列表渲染。

### 2.2 工程健壮性（"自造轮子"的底气）
- **零反射自研依赖**：`JsonLib/XmlLib/PngEncoder/JpegCodec/BmpCodec/TrueTypeFont` 等——对安全敏感场景是优势（无供应链攻击面）。
- **重试/容错成体系**：`RetryPolicy.cs` 智能重试、`FallbackLLM` 6 模型跨供应商回退（罕见：可在 Key 失效时自动切换，非单一供应商绑定）、`ContextManager` 三层上下文压缩。
- **安全设计齐全**：`BashGuard`(70+ 禁止命令 + 47 安全白名单) + `SandboxManager` + `PathSafety` + `FileIgnoreManager` + `FileLockManager`。
- **自测规模大**：`SelfTest` 3070 项自测 + `Benchmark`，作为无外部 CI 依赖的纯 CLI 项目，质量保障意识强。

### 2.3 记忆与持久化
- `StructuredMemory` + `EmbeddingStore/SemanticMemory`（向量语义检索）+ `SharedMemoryManager`（团队共享）——**语义记忆能力**对齐 Cline/Cruse 较新的方向，且内置向量存储（Claude Code 需依赖其自家记忆，Codex 较弱）。
- `SessionManager` 会话持久化、`CheckpointManager` 检查点（对齐 Codex/Claude checkpoints 方向）。

### 2.4 批量与并发
- `Batch/BatchRunner.cs` 多仓库并行 + **worktree 隔离** + 聚合报告——**这是相对小众却很实用的能力**，适合大规模多仓库重构，多数竞品 CLI 不具备。

## 3. 劣势与差距（源码支撑）

### 3.1 生态与信任度（最大短板）
| 差距 | 说明 |
|---|---|
| **无 IDE 官方扩展** | Cursor/Cline/Windsurf 深度嵌编辑器；WayCoder 只有自研 Avalonia GUI。`--json` 已为桥接铺路，但无 VS Code/JetBrains 扩展是结构性短板 |
| **非主流语言/运行时** | .NET 10 单平台生态 vs Claude/Codex/Aider 的 Node/Rust/Python。用户安装门槛高（需 .NET SDK），竞品多为自包含二进制（Codex 单文件 Rust） |
| **缺少商业背书/云能力** | 无云端 agent、无 IDE 云同步、无官方模型托管。Cursor 云端上下文、Claude 官方 API 是其护城河 |
| **文档/社区薄弱** | `docs/` 较薄，无像样中文文档站与示例；竞品有丰富文档与社区 |

### 3.2 安全沙箱层级
- `SandboxManager`/`BashGuard` 是**软件级**黑/白名单防护；Claude Code、Codex 采用**内核级沙箱**（Seatbelt/Landlock/seatbelt），可真正做到零权限隔离 + 网络隔离。这是纵深防御上的实质差距。

### 3.3 架构优雅度
- **配置单 `.env`**（67 项）vs 竞品多作用域（全局 + 工作区 + 项目级 JSON/TOML）。可维护性弱。
- 权限确认**直接调用** vs Crush 的**事件总线 pub/sub 解耦**。插件/UI 扩展受限。
- 插件系统为**编译期**（需重新编译），vs Cline/MCP 的**运行时动态**插件。灵活度差。

### 3.4 性能/体积
- .NET 启动与常驻内存高于 Rust 类竞品（Codex/Crush/Aider）；自研解码器体积大，`waycoder.exe` 偏大。终端响应速度在低配机器上有感。

## 4. 竞品各自优缺点速览

### Claude Code
- ✅ 长程规划/多步骤工程最强；subagents + skills(CLAUDE.md/SKILL.md) 生态成熟；hooks 深度定制；内核沙箱。
- ❌ 重度绑定 Anthropic API；闭源；无自由模型接入；国内访问不便。

### OpenAI Codex CLI
- ✅ Rust 极简快、`--json` 可脚本化、OAuth 登录、Seatbelt 沙箱、单文件分发。
- ❌ 工具集精简、功能面窄；依赖 OpenAI 生态；图形交互弱。

### Cursor
- ✅ 最强 IDE 集成、多 agent 并行、云端上下文、图形化审批。
- ❌ 闭源商业；模型选择受限；非 CLI 自动化友好；付费。

### Cline
- ✅ 开源透明、模型无关（可接任意 OpenAI 兼容）、MCP 生态活跃、社区大。
- ❌ 依赖 VS Code 宿主（无独立 CLI）；单仓库多 agent 能力弱；性能一般。

### Aider
- ✅ Git 优先理念清晰、repo map 精准、轻量、纯终端、diff 编辑可靠。
- ❌ 功能单一（专注 git 编辑）；无 GUI；多模态/工具集少；无记忆系统。

### Crush
- ✅ 事件总线 pub/sub 架构优雅、面向 power user、开源。
- ❌ 生态小、工具集有限、功能较新不成熟。

## 5. 结论：差异化定位

WayCoder 的**真实差异化**不在"对标 Claude Code"（生态/沙箱/品牌无法企及），而在：
1. **单二进制全栈工具**（多模态 + 文档解析 + 批量 + TUI + GUI）——"本地全能 agent 工作台"。
2. **多模型跨供应商回退 + 模型无关**——国内/自托管模型友好的独立 agent，这是 Claude/Codex/Cursor 无法给的开源自由度。
3. **语义记忆 + 团队共享 + 批量并行**——面向团队与多仓库工程实践的差异化。

最应补的 3 个方向（按性价比）：
1. **VS Code 扩展**（`--json` 已铺路，最快放大触达）。
2. **运行时动态插件/MCP 深化**（对齐 Cline，补齐编译期插件的短板）。
3. **内核级沙箱 + 多作用域配置**（补齐纵深安全与可维护性）。
