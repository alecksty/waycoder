# 命令行参数：三层设计（宿主 → VM → 程序 → 语言绑定）

> 现状（2026-09-22 勘察）：**只有 C/C++ 前端认识 `argv`**（它按 C 的调用约定从帧里读），
> 其余 **20 门语言一个字都没有** —— `grep -rn argv VMLPrepares/*/` 只有 CCompiler / CppCompiler 命中。
> 而运行时的 `CommandLineArgs` 属性一直是空的：**没有任何宿主往里放过东西**。
> 也就是说：参数这条路上，"能传"与"怎么取"两头都断着。

## 0. 一句话

**宿主喂一份字符串数组 → VM 存起来 → 程序可以用两种方式取：C 的 `main(argc, argv)` 入口帧（已有），
或者新开两个 syscall（`#62`/`#63`）按需取。各语言的绑定负责把它翻成 `sys.argv` / `os.Args` / `ARGV` 这些习惯叫法。**

## 1. 第一层：宿主怎么给（三个入口，同一份数据）

| 入口 | 形式 | 说明 |
|---|---|---|
| 桌面 CLI | `vmlcli prog.c --arg -l --arg foo` | **可重复的 `--arg <一个值>`**，不要「一行切空白」——本仓已经踩过"命令按空白切分、路径带空格就断成两截"（`ShellCommandRegistry.Split` 不做引号解析） |
| 手机命令行页 | `vml run prog.c -l foo` | `vml` 工具把**第一个非选项 token 之后的全部**当参数透传 |
| 界面入口 | 「运行参数」输入框 | 一行一个参数（不做引号解析，与上面两条同一份切分规则） |

三条最终都落到同一个地方：`VmRuntime.CommandLineArgs`（`List<string>`，**已存在**，只是没人赋值）。
约定 **`CommandLineArgs[0]` = 程序名**（`argv[0]` 的语义），由宿主决定：
CLI 给源文件名、手机给程序名。宿主一个参数都不传时，VM **仍要补 `argv[0]`**
（C 保证 `argc >= 1`，而且老程序常拿 `argv[0]` 打用法）——这一条已经在本轮实现进入口帧了。

## 2. 第二层：VM 怎么交（两条路，都要留）

### 路 A：入口帧（已有，`main(argc, argv)` 的语言直接用）

C 的约定里 `call` 把**返回地址**压栈、参数落在它**之上**，所以被调用方读参数的位置是
`[R12+12]`（第一个）、`[R12+16]`（第二个）……运行时不论特权级都要把这三格搭好：
**argv、argc、返回地址**（返回地址给 0 = 从 `main` 返回即结束程序）。**已实现**（2026-09-22，
判据 `scripts/vml-c-probe/cases/43-argv-and-stack.c`）。

### 路 B：新开两个号（其余 21 门语言 + 想按自己习惯取的程序）

按本仓铁律「**新能力一律走新号**」（不给 `#54`/`#59` 加参数 —— 老程序那几只寄存器里
是它自己上一句留下的值，宿主无从判断"这是不是真给了"）：

| 号 | 名字 | 调用 | 返回 |
|---|---|---|---|
| **62** | `ArgCount` | 无参 | R0 = 参数个数（**含 `argv[0]`**，故恒 ≥ 1） |
| **63** | `ArgGet` | R0 = 序号 | R0 = **字符串地址**（NUL 结尾；越界给 0） |

**两条都必须登记进 `SyscallNumber.UserAllowed`** —— 用户态只放行白名单里的号，
漏了会打 `Permission denied: syscall N requires kernel mode` 并把 R0 置成错误码
（表现是"取到的参数全是垃圾"，最难查的一类）。

**为什么 `ArgGet` 返回"地址"而不是"写进调用方缓冲区"**：
- 与现成的 `#59 GetInfo`（`R0=TypeId → R0=string_addr`）**同一形状**，实现最省；
- 缓冲区版要先知道长度（两趟调用）或者定义截断语义，而 22 门语言的字符串表示各不相同；
- 让**绑定层**自己拷：C 的 `char*` 直接就能用；BASIC 声明成 `NATIVE FUNCTION ... STRING`；
  Scheme/Python 由绑定拷成自己的 string/list ✓。

⚠ 返回的地址**只读**（是 VM 内部那份），要改就自己拷一份 —— 这条要写进接口文档。

## 3. 第三层：各语言绑定（一人一行，按语言习惯）

| 语言 | 用户代码里怎么写 | 绑定怎么做 |
|---|---|---|
| C / C++ | `int main(int argc, char **argv)` | **入口帧**（已有）；`waycoder_ui.h` 再补 `ui_argc()` / `ui_arg(i)` 给 `int main(void)` 的程序 |
| Python | `sys.argv` | `Lib/python/` 里把 `sys.argv` 造成 list（或 `sys_argv()`） |
| Lua | `arg` 表 | 造表：`arg[0]` = 程序名、`arg[1..]`、`arg[-1]` = 解释器名（Lua 语义） |
| Ruby | `ARGV` | |
| JavaScript | `process.argv` | |
| Go | `os.Args` | |
| Java | `String[] args` | |
| Rust | `std::env::args()` | |
| Scheme | `(command-line)` | |
| Pascal | `ParamCount` / `ParamStr(i)` | 1 基 |
| BASIC | `COMMAND$` / `ARGV(i)` | QBasic 的 `COMMAND$` 是"整行"，`ARGV` 另给 |
| ... | （22 门按各自习惯补齐） | |

**先做 C 的 `ui_arg*`，再做 Python/Lua/JS 这三门**（老程序里最常见），其余按需补。

## 4. 判据（每条都必须有 —— 用户 2026-09-22 定的规矩）

1. `scripts/vml-c-probe/cases/45-argv-pass.c`：宿主真的把参数传进来了
   （`main` 的 `argv[0..2]` 与 `#62`/`#63` **两条路取到同一份**）——
   这要求 runner 支持 `// ARGS: -l foo` 这种声明（照 `// STDIN:` 的写法）。
2. 无参数时：`ArgCount >= 1`、`ArgGet(0)` 可读、`ArgGet(1) == 0` ✓（已由 `cases/43` 钉住一半）。
3. 越界：`ArgGet(99)` 给 0（**不是**随机地址）。
4. 每门语言绑定各一条（并入现有的全语言冒烟脚本，不另造轮子）。

## 5. 边界与不做的事

- **`.vml` / `.vmb` 产物里不含参数** ⇒ 参数永远是**运行时**喂的。
  这条正好对上手机那条「编译成 `.vml` 再独立运行」的路：同一个 `.vml` 可以带不同参数跑。
- **`#62`/`#63` 与特权级无关**（参数是 ABI/环境的事，不是内核能力）—— 但**仍要走白名单**
  （白名单是"哪一号允许用"，与 `privilegeLevel` 是两件事）。
- **不做引号解析**：`--arg` 可重复就是为此（要带空格的参数就整段当一个值给）。
- **不做环境变量**（`environ`）：那是另一件事，等有真实老程序需要再说 ——
  现在做只会多一层没人用的抽象。
