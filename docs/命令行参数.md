# 命令行参数：三层设计（宿主 → VM → 程序 → 语言绑定）

> 现状勘察（2026-09-22）：**只有 C/C++ 前端认识 `argv`**（它按 C 的调用约定从帧里读），
> 其余 **20 门语言一个字都没有** —— `grep -rn argv VMLPrepares/*/` 只有 CCompiler / CppCompiler 命中。
> 而运行时的 `CommandLineArgs` 属性一直是空的：**没有任何宿主往里放过东西**。
> ⇒ 参数这条路上，"能传"与"怎么取"两头都断着。

## 0. 一句话

**宿主喂一份字符串数组 → VM 存起来（唯一真源）→ 程序用两种方式取：
C 的 `main(argc, argv)` 入口帧，或者 `#62`/`#63` 两个 syscall。
各语言的绑定负责把它翻成 `sys.argv` / `os.Args` / `ARGV` 这些习惯叫法。**

## 1. 第一层：宿主怎么给（三个入口，同一份数据）

| 入口 | 形式 | 状态 |
|---|---|---|
| 桌面 CLI | `vmlcli prog.c --arg -l --arg foo` | ✅ 已实现 |
| 手机命令行页 | `vml run prog.c -l foo`（多出来的 token 全当参数） | ⏳ 待接 |
| 界面入口 | 「运行参数」输入框（一行一个参数） | ⏳ 待接 |

三条最终都落到 `VmRuntime.CommandLineArgs`（`List<string>`）。
**`argv[0]` 由宿主决定**：CLI 给源文件名、手机给程序名；宿主一个参数都不给时，
运行时**仍会补一个 `argv[0]`**（C 保证 `argc >= 1`，老程序常拿它打用法）。
CLI 的 `--arg` **刻意不做引号解析**（本仓踩过"按空白切分、路径带空格就断成两截"，
见 `ShellCommandRegistry.Split`）：要带空格的参数就整段当一个值给 —— `--arg "hello world"`。

## 2. 第二层：VM 怎么交（两条路，都要留）

唯一真源 = 运行时那个 `_argvStrings`（`LoadProgram` 里按 `CommandLineArgs` 铺好），
**入口帧与 `#62`/`#63` 两份消费都读它** —— 两处各算一份就是
"`main` 拿到的和 `ui_arg` 拿到的不是一回事"这种最难查的分叉。

### 路 A：入口帧（✅ 已实现）

C 的约定里 `call` 把**返回地址**压栈、参数落在它**之上**，所以被调用方读参数的位置是
`[R12+12]`（第一个）、`[R12+16]`（第二个）……运行时不论特权级都要把三格搭好：
**argv、argc、返回地址**（返回地址给 0 = 从 `main` 返回即结束程序、退出码取 R0）。
判据 `scripts/vml-c-probe/cases/43-argv-and-stack.c`（含"没参数时 `argc` 也得是 1"）。

### 路 B：两个新号（✅ 已实现）

按本仓铁律「**新能力一律走新号**」（不给 `#54`/`#59` 加参数 —— 老程序那几只寄存器里
是它自己上一句留下的值，宿主无从判断"这是不是真给了"）：

| 号 | 名字 | 调用 | 返回 |
|---|---|---|---|
| **62** | `ArgCount` | 无参 | R0 = 参数个数（**含 `argv[0]`**，故恒 ≥ 1） |
| **63** | `ArgGet` | R0 = 序号，R1 = 缓冲区，R2 = 容量 | R0 = **写入的字节数**（不含结尾 NUL）；越界/缓冲区无效 = **-1** |

两条都必须登记进 `SyscallNumber.UserAllowed` —— 用户态只放行白名单里的号，
漏了会打 `Permission denied: syscall N requires kernel mode` 并把 R0 置成错误码
（表现是"取到的参数全是垃圾"，最难查的一类）。**与特权级无关**：参数是 ABI/环境的事，
不是内核能力（白名单管的是"这一号允许不允许用"，两件事）。

**为什么 `#63` 是"写进调用方缓冲区"而不是"返回字符串地址"**（这一点设计时改过一次）：
返回地址看着更省事，但**拷贝逻辑会落到每一门语言的绑定里**（22 份拷贝循环，
还各要处理越界与截断）；写进缓冲区则**运行时一处实现、22 门绑定都只是一行 syscall** ——
与现成的 `ui_store_get` / `ui_call_json` 同一套（宿主本来就没有能"交还"的堆）。
本仓头号坑正是"同一规则两处实现"，这里从一开始就避开。

## 5. 边界与不做的事

- **`.vml` / `.vmb` 产物里不含参数** ⇒ 参数永远是**运行时**喂的 ——
  同一个 `.vml` 可以带不同参数跑（手机那条「编译成 `.vml` 再独立运行」的路正需要这个）。
- **返回的字符串是 VM 内部那份**：`#63` 直接拷进调用方缓冲区，调用方那份自己管生命周期。
- **不做引号解析**：`--arg` 可重复就是为此。
- **不做环境变量**（`environ`）：那是另一件事，等有真实老程序需要再说 ——
  现在做只会多一层没人用的抽象。
