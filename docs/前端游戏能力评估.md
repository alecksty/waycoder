## 1. 前置事实（先把链摸清）

| 环节 | 位置 |

**调用约定（第一个坎）**：包装函数读 `[R12+12]` = 调用方**最后压**的那个 = C 的第一个参数
⇒ 实参必须**逆序压栈**。一个前端若正序压栈，或把未知函数名当变量（间接 `call R0`），就直接调不通。

**已修的三条前置问题**（补丁 0009）：
1. 原来只有 c / basic / python 挂了 `vmlui.vml`，其余 19 种 `Libs=""` ⇒ 非 C 语言写 `ui_rect(...)`
   直接**运行期**报 `未找到标签: ui_rect`（Go 实测：编译链接全过、一跑就崩）。
2. **更严重**：给 c/basic/python 挂 vmlui 那三处**本来就是我们本地的改动、从来没进补丁**，
   而 `vmltool.config.xml` 由 `sync.sh` 用 `cp` 覆盖 ⇒ **跑一次同步，C 的游戏示例就会全部编不过**。
3. `scripts/check-vml-patches.sh` 此前只比八个目录、没看这个文件 —— 判据漏一个文件，
   那道防线对它就等于不存在。现已连同 `VERSION` 纳入比对。

## 4. 逐条根因（带证据）

### 4.1 Go —— 条件跳转编成了"跳寄存器"，而那两个寄存器从没被赋值

```
sta_3:  move R0 [R14-4]      ; i
        cmp R1 R0
        jl R30               ; ← 想跳"真分支"，目标却是**寄存器**
        move R0 #0
        jmp R31              ; ← 同上
L6:     move R0 #1
```
证据两条：① 整份 68k 条指令里 **`move R30` / `move R31` 出现 0 次**（`R24–R31` 其实是
**L0–L7 长整数寄存器**）；② VM 的 `ExecuteJmp`（`VMLRuntime.Instructions.cs:901`）只处理
`LABEL` 与 `IMMEDIATE`，**寄存器操作数两个分支都不匹配 ⇒ 静默什么都不做**。
⇒ 表现是死循环（`--vmtimeout 5` 到点被杀、一帧都没出）。
**修法**：控件流降级要发标签跳转（照 C 前端：`move R0 L80190001` 把标签**地址**装进寄存器，
或直接 `jmp Lxxxx`）。⚠ 光让 VM 支持寄存器间接跳转**不够**——那两个寄存器本来也没人赋值。

### 4.2 Pascal / Kotlin —— 同一个病，落在**数组的越界检查**上

```
        cmp R3 R4
        jge R24              ; 又是跳寄存器
        move R0 #-1
        syscall #3           ; ← 于是"越界就退出"这条分支**永远执行**
```
⇒ 程序连窗都没开就退了（实测：Pascal 的"数组 + 循环"直接没有帧）。循环过关是因为
循环用的是另一条（正确的）跳转路径。

### 4.3 JavaScript —— 未知函数名被当成**变量**，调用成了间接跳转；且实参**正序压栈**

```
        move R1 var_ui_rect    ; 把 ui_rect 当成一个变量
        call R0                ; 间接调用 ⇒ 运行期跳到野地址
```
实参压栈顺序还是**书写顺序**（`10,10,80,40,色,1,0,0`），而包装读到的第一个参数是
**最后压的那个** ⇒ 即便调用成功，参数也全错。两处都要修。

### 4.4 C# —— 全局变量读成了地址（**已修**）+ 带参方法参数串槽（**未修**）

① 已修（patch 0010）：`const int N = 5;` 实测画出 **1026** 个方块而不是 5 —— 数据的读取用了
   `OperandType.LABEL`，而 LABEL 是"标签的**地址**"（C 那边正是用它物化指针）⇒ `i < N` 变成
   `i < 地址(var_N)`。改成 `MEMORY`（两读一写），并给**类字段**补上"登记数据段 + 折初值"
   （此前字段被当成栈上局部变量，初值整个丢掉）。
② 未修：**带参方法的参数会串**。`a1(x)` / `a2(x,y)` / `a3(x,y,c)` 各画一个方块，只有前两个位置对；
   `a4(x,y,w,h)` 连尺寸都不对。而**结构完全相同**的 `box(x,y,color)` 在另一个程序里又是对的
   —— 像是**参数槽在不同方法间互相踩**（与补丁 0002 修的"暂存槽撞车"同族）。
   ⇒ **这一条不修，别指望用 C# 写游戏**（游戏里每个动作都要调方法）。

### 4.5 Swift —— ①全局初始化成了死代码（**已修**）②函数的局部变量漏进全局（**未修**）

**① 已修（patch 0011）**：程序定义了 `func main()` 时，**顶层那段语句永远不会执行** ——
而全局变量/全局数组的初始化恰恰就在那段里（`var A = [...]` 生成的是"把数组基址存进 var_A"）
⇒ `var_A` 恒为 0 ⇒ 所有 `A[i]` 读写都落在地址 4/8/… 那片**低内存**上。
同一个函数内读写偏移一致所以"看着正常"，跨函数立刻露馅（`A[1] = 3` 读回来是别的值）。
修法**不搬指令、只挪标签**：入口仍旧指回顶层块，块尾 EXIT 前插一句 `call __user_main`。
⚠ 序列化器认的是**指令流里的 LABEL 伪指令**、不是编译器那张 `labels` 表 —— 只改表会白改一次
（第一版就是这样，出图一看才发现）。

**② 已修（同一条补丁）**：函数里的局部变量**漏进全局数据段**。`func count5() -> Int
{ var i = 0; var s = 0; while i < 5 {…} return s }` 实测返回 **3** 而不是 5；数据段里能看到
`var_i` / `var_k` / `var_tries` / `var_c` / `var_r` 这些**函数局部**。两条都不对：序言只给
**参数**留帧位、`GenerateVariableDecl` 无条件写数据段 ⇒ **同名局部在不同函数间互相踩**
（游戏里 `draw`/`step`/`occupied` 三处都有 `var_i`）。改法：序言递归预扫描函数体留帧位
（`ReserveLocals`）+ 声明处**栈帧优先**。验证：`i`/`s` 落到 `[R14-4]`/`[R14-8]`，
方块宽度**逐像素量**出来 40 = 5×8 ✓。

**③ 已修（同一条补丁）**：**读数组元素读回来的是字节偏移，不是元素值** ——
`GenerateIndexAccess` 最后一句 `MOVE [Mem("R1")], R0` 把 dest/src 写反了（`MOVE dest, src`），
于是"读"变成了"把偏移存进去"、R0 里留着的正是偏移。逐像素量出来的三个数
（`A[2]`→12 = 2*4+4、`A[16+k*2]`→92、`A[3]`→16 = 3*4+4）**全对得上偏移公式**。
改成 `MOVE R0, [R1]` 后，常量下标 / 变量下标 / 算术下标 / 动态写后读 = **24 / 24 / 32 / 56 像素**，
与期望逐一吻合 ✓。**这是"地址当值"那一族的第四次**（C# 的 LABEL/MEMORY、BASIC 的 `MOVE reg, R2`）。

**④ 最后一步（已定位并修掉）**：贪吃蛇当时能画出窗口 / 棋盘 / HUD / 食物 / **一节蛇身**，
而同一份状态在 `main` 里量是对的 ⇒ 状态没写错，是读取那一段的问题。见下条。

**⑤ 括号表达式恒等于 0 —— 三家前端同一个洞（v0.96.189 修）**

`GenerateExpression` 的 switch 里**没有 `ParenthesizedExpression` 分支**，落进
`default:` 被静默编成 `move R0 #0`。解析器明明建了这个节点
（`new ParenthesizedExpression(expr)`）、代码生成却没接 —— **Swift / C# / JavaScript 三家都是**
（15 个表达式类型里只漏了这一个；Java 接上了）。

**为什么查了四轮才找到**：症状是"`A[16 + (k) * 2]` 六次写入全落到同一个槽，
换纯常量下标 `A[16]…A[21]` 就全对"，看起来完全像"算式下标不能在多条语句里复用"——
而**真因是下标恒为 `16 + 0*2 = 16`**（`(k)` 折成 0），跟"复用"没有半点关系。
同一个洞还让 `draw()` 里的棋盘格 `(c + r) % 2 == 0` 从来没交替过（图元数 368 → 188，
差值 180 正好是 20×18 的一半，这条是修好之后的**独立佐证**）。

**判据**：不看现象猜，**读生成的汇编**（`vmlhost asm`）——修前 `(k)` 处就是 `move R0 #0`，
一步定位。这个手段前面几轮没用上，才绕了远路。

**修法**：补 `case ParenthesizedExpression paren:` 递归生成内层；类型推断同步补一条；
`default:` 从"静默发 0"改成**抛 `CodeGenerationException`** —— 这类"编译全绿、跑起来错"
的故障最该编不过（与 `DrawCommand.Vector` 定成必需成员同一个理由）。

**结果**：`Examples/swift/snake.swift` **跑通**，逐像素量：蛇头 316 像素（1 格）、
蛇身 632（2 格）、食物 316（1 格）—— 三个数全是精确整格。

**另外两条写法约束**（至今成立，与补丁无关）：模块级**标量**（`var n = 5`）读出来是垃圾
（与 C# 修之前同一个病）；`var w = ui_scr_w()` 直接喂给 `ui_win_open` 会开出 **60×64** 的小窗，
经一道局部变量才正常。**这两条不是偏好，是实测** —— 游戏里所有状态因此都放数组、常量都写成局部。

- 干净的部分：1/2/3 参方法的位置与取值都对；数组读写、返回值、全局数组写读（同一函数内）都对；
  定时器 + `ui_wait_msg` 的通路也通。
- 曾经坏的部分（都已修）：跨函数读全局数组读回偏移、函数局部漏进全局、括号恒等于 0。

## 5. 库自带的三层"弱前端兜底"（设计意图就是"哪门语言都能写游戏"）

`Lib/shared/src/vmlui.c` 里已经准备好了，**写游戏前先用它们**：

| 兜底层 | 接口 | 给谁用 |
|---|---|---|
| 不碰指针的消息 | `ui_wait_msg(ms)` / `ui_poll_msg()` / `ui_msg_type/a/b` | 取不了址的语言 |
| **宿主侧整数网格** | `ui_gclear` / `ui_gset` / `ui_gget`（256 个 int，越界安全失败）| **没有可靠数组**的语言（注释点名 Python / BASIC）|
| 方块几何 + 旋转 | `ui_piece_init` / `ui_piece_cell(pid,rot,which)` | 没有位运算的语言 |

⇒ 一个前端只要能做到"**传整数、循环、分支**"，棋盘就能放在宿主侧、游戏就能写。
真正划不来的只有 §4.1–4.3 那三门（调用或跳转本身是坏的）。
