# 上架逐屏操作（App Store Connect）

[上架资料包](上架资料包.md) 讲**填什么**（口径、文案草稿、问卷答案、为什么这么定），
本文讲**怎么点**：每个阶段点哪个按钮、填什么字段、看到什么才算过。
打包与上传见 [上架AppStore](上架AppStore.md)。

> ⚠ App Store Connect 的界面文案会变。本文按当前中文界面的按钮名写，英文名附在括号里；
> **以你屏幕上看到的为准，字段语义不变**。

## 一、先备好这四样

做任何一步之前先准备，否则中途会卡住：

| 要件 | 怎么来 | 注意 |
|---|---|---|
| **沙箱测试账号** | App Store Connect → 用户与访问 → 沙箱 → 测试人员 → `+` | 邮箱必须是**从未注册过 Apple ID** 的地址（用过的会被拒）；国家/地区选**美国**（与 $9.99 定价区一致）；密码与三个安全问题答案**记下来**，购买弹窗会问 |
| **能装到真机的开发签名包** | Visual Studio 配对 Mac 后选真机部署；或命令行 `dotnet build -f net10.0-ios27.0 -c Debug -p:RuntimeIdentifier=ios-arm64 -t:Run -p:_DeviceName=:v2:udid=<UDID>` | ⚠ `build-ios-appstore.sh` 出的 **App Store 类型 .ipa 装不上真机**（它只能经 Transporter/TestFlight 分发）。内购验收必须走开发签名包 |
| **审核用的模型 API Key** | 你自己的服务商账号 | 额度够用、有效期覆盖整个审核期。**这是 4.2「功能不足」的唯一防线** |
| **截图** | 跑起来的 App | 6.7" / 6.5" / 5.5" iPhone **各一套**，外加 **iPad 一套**（`UIDeviceFamily` 含 iPad，缺了会被直接拦） |

## 二、阶段 0：让账号「能收钱」

内购提交入口要等这三项**全部**「生效」才出现。只填一半是最常见的卡点。

| 点哪里 | 填什么 | 看到什么才算过 |
|---|---|---|
| 协议、税务和银行业务 → **协议** → 「付费 App」行 → 查看并同意 | 勾选条款、填写联系人 | 该行状态由「待处理」变「**生效**」 |
| 同页 → **银行账户** → 添加银行账户 | 账户持有人姓名（与身份证一致）、银行名称、SWIFT/BIC、账号、银行地址 | 状态「生效」 |
| 同页 → **税务信息** → 设置税务信息 | 个人 → **W-8BEN**；国家 China；TIN 填**身份证号**；⚠ **务必在第 2 部分勾「协定优惠」** | 状态「生效」，预扣率显示 **10%**（不勾是 30%） |

## 三、阶段 1：建 App 记录

「我的 App」→ `+` → 新建 App：

| 字段 | 填什么 |
|---|---|
| 平台 | iOS |
| 名称 | 30 字以内；可用英文名先占位，正式名称按语言在版本信息里分设 |
| 主语言 | **English**（先上海外区就先建英文） |
| 套装 ID | **`com.tanso.dolaima`**（逐字；Explicit 类型，不能用通配符） |
| SKU | 自编一个内部编号（如 `dolaima-ios-001`），不对外 |

建完后：

- **App 信息 → 类别**：主类别「开发者工具」（Developer Tools），次类别「效率」（Productivity）
- **价格与销售范围 → App 销售范围**：默认是「所有国家或地区」 ⇒ 按已定口径
  **取消勾选中国大陆**（先只上海外，备案那条线见 [上架资料包](上架资料包.md) §4）
- **价格与销售范围 → App 价格**：**免费**（App 本体免费；内购价格在阶段 2 单独设）

## 四、阶段 2：建内购产品

功能 → **App 内购买项目** → `+`：

| 字段 | 填什么 |
|---|---|
| 类型 | **非消耗型**（Non-Consumable）—— 一次性买断、可跨设备恢复 |
| 产品 ID | **`com.tanso.dolaima.full`** —— 与代码里 `FreeTierPolicy.FullEditionProductId` 逐字一致。⚠ **建完改不了**，只能新建 |
| 参考名称 | 全能版（内部用，用户看不到） |

建完再进去补三样：

| 点哪里 | 填什么 | 看到什么才算过 |
|---|---|---|
| 价格 → 添加价格 | 价格点选 **$9.99**（美国区基价，其它区自动换算） | 价格列显示 US$9.99 |
| App 内购买项目信息 → **本地化** | 显示名称与描述**中英各一份** —— **这才是用户看到的**，不是"参考名称" | 两种语言都「已添加」 |
| **审核信息** | 一张能看出解锁入口在哪的截图（设置 → 全能版） | 状态到「**准备提交**」 |

⚠ **首次内购必须跟着某个 App 版本一起提交**，不能单独提。

### 年龄分级：目标 13+（口径已定）

**口径：对标主流 AI 助手。** 当前 App Store 上 ChatGPT / Gemini / Microsoft Copilot 都是 **13+**，
Perplexity 是 18+（差别一般出在它带**用户可自行导航的内置浏览器**）。道码按前者定。

**关键那条 —— 「不受限的网络访问 / Unrestricted Web Access」答「否」**：

- 苹果的定义是「**让用户能导航并查看网页，例如内置浏览器**」（带地址栏、能自由上网的
  WebView / 浏览器）。这条**会把分级推向最高档**。
- 道码**没有内置浏览器、没有 WebView、没有地址栏**。联网走的是 `fetch` / `download` 这类
  **工具**：把某个 URL 的内容取回来当**文本**交给模型，不是让用户去浏览网页。
  ⇒ 按定义应答「**否**」，与 ChatGPT / Gemini 一致（它们也是模型侧取网页）。

⚠ **风险与话术**：分级是苹果按答案算出来的（**最严的答案赢**），不能自己选低。
若审核员认为实际具备该能力而来问，答复就是上面那段（无 WebView、内容以文本进模型、不渲染网页）。

⚠ **分级体系 2025 年改版过**：旧的 12+ / 17+ **已取消**，现在是 **4+ / 9+ / 13+ / 16+ / 18+**；
新版问卷**专门覆盖 AI 聊天/助手类功能**，且要求 **2026-01-31 前完成**，否则无法提交更新。

其余题目按实答（无暴力、无赌博、无成人题材、无恐怖内容）。隐私政策里已对应写明
「**不面向 13 岁以下儿童**」，与 13+ 口径一致。

## 七、内购真机验收（上架前必做）

代码只做过编译验证，真实交易必须走一遍沙箱。**十条全过才算完**。

### 前置

1. 沙箱测试账号已建（见第一节），并已在真机上登录：
   **设置 → App Store → 拉到底 → 沙箱账户**（Sandbox Account）。
   ⚠ **不要退出你真实的 Apple ID** —— 沙箱账户是独立入口。若你的系统版本没有这个入口，
   则在购买弹窗弹出时输入沙箱账号即可。
2. 真机上装的是**开发签名包**（上架 .ipa 装不上真机）。
3. 后台内购产品状态已是「准备提交」—— 产品没建好时购买按钮上**不会显示价格**。

### 十条判据

| # | 怎么操作 | 看什么 | 期望 |
|---|---|---|---|
| 1 | 文件页点开一个 `.c` → VML 运行 | 有没有被锁 | **正常编过**（免费档不能因为内购把 C 也拦了） |
| 2 | 文件页点开一个 `.py` → 看菜单 | 菜单项文案；点下去 | 显示「需全能版 🔒」；点下去弹"去哪解锁"，**不执行编译** |
| 3 | 文件页点开一个 `.vml` → VML 运行 | 产物 | **正常**编出 `.vmb`（VML 汇编本就在免费档内） |
| 4 | 设置 →「编译」组 | 「优化级别」这一项在不在 | **整项不渲染**（不是置灰），旁边有一句说明它属于全能版 |
| 5 | 设置 → 全能版 → 点购买 | 按钮文字；弹窗；付完回哪 | 按钮显示「购买 全能版 · <价格>」；弹窗底部显示 `[沙箱]`；付款后**立即**变「已解锁全能版」，不用重开 |
| 6 | 上滑杀掉 App → 重开 → 设置 → 全能版 | 状态 | 仍是「已解锁」（本地缓存生效） |
| 7 | **删掉 App → 重新部署 → 点「恢复购买」** | 按钮可点否；文案 | 重装后先是未解锁 ⇒ 按钮可点；点完变「已解锁」 |
| 8 | 换一个**没买过**的沙箱账号 → **先删 App 重装** → 点「恢复购买」 | 文案与最终状态 | 「没有找到可恢复的购买记录」；状态**保持未解锁** |
| 9 | 开飞行模式 → 点「恢复购买」（需在未解锁态） | 文案；状态 | 报恢复失败；**状态一个字没动**（不会被误置成已解锁） |
| 10 | 沙箱发起退款 → **删 App 重装** → 点「恢复购买」 | 文案与状态 | 「没有找到可恢复的购买记录」；**保持未解锁** |

### ⚠ 第 7/8/9/10 条要特别注意

**第 7/8/9 是「恢复购买」这个动作的全部难点**，也是审核员会实际点的那一下 ——
别只验"买了能解锁"就收工。

**第 10 条已修正**（原判据"退款后重开 App 就收敛"**按现在的代码做不到**）：

- **根因**：本地解锁状态是缓存的，退款后缓存仍是"已解锁"；而设置页的
  `FullRestoreBtn.IsEnabled = supported && !full` —— **已解锁时「恢复购买」按钮是禁用的**，
  唯一的收敛路径点不到。iOS 的 StoreKit 也不会把退款作为交易更新推给应用。
- **所以判据改成**：退款后的收敛**通过"删掉重装 + 恢复购买"发生**，不是"重开 App 自动收敛"。
- **退款怎么触发**：走沙箱账号在 Apple 的退款申请页发起。
  若沙箱环境不提供退款入口，本条降级为**推理验证** —— 在设置里手工清掉解锁状态后
  重装 + 恢复，确认收敛路径成立即可。
- **想让"不重装也能收敛"是代码改动**（解锁态也允许刷新购买状态，或启动时静默恢复一次）。
  本轮**有意不做**，记在这里免得下次又绕回来。

### 顺带要看的

- 免费档**不受影响**：`Preferences` 里没有解锁标记时，C 与 VML 汇编照常可用。
- 从「设置 → 关于 → 使用说明与隐私」能打开隐私政策与使用条款，中英各看一遍（离线也应可看）。
