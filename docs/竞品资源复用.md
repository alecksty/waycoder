# 竞品资源复用指南

> 竞品 = Claude Code / Crush / Cursor / Aider / Cline / OpenCode 等编程智能体。
> 本文回答一个核心问题：**这些竞品生态里的插件、MCP、LSP、Skill，哪些能直接搬进 WayCoder 用？**

**一句话结论**：判断标准是「协议是否开放统一」——协议开放的（MCP / LSP server 生态 / SKILL.md）可直接复用；各家私有 API 的（插件外壳）不能复用，但内部封装的开放资源可以「拆包」复用。

## 分级总览

| 资源 | 可共用程度 | 依据 |
|---|---|---|
| **MCP** | ✅ 完全共用 | 开放协议（JSON-RPC 2.0），跨工具标准 |
| **LSP server 生态** | ✅ 完全共用 | 开放协议 + 同一批 language server 二进制 |
| **SKILL** | 🟡 高度共用 | 标准 `SKILL.md` 格式，细节字段需容错 |
| **插件** | ❌ 外壳不可共用 / 🟡 内部资源可拆 | 各家私有 API |

---

## 1. MCP —— 完全共用（兼容度最高）

MCP（Model Context Protocol）是 Anthropic 定义的开放协议，协议层统一（`initialize` → `tools/list` → `tools/call`），所以竞品配置的 MCP 服务器 WayCoder 能直接连。

- Claude Code / Cline / Cursor 配置的 MCP 服务器 → 填进 `.waycoder/mcp_servers.json` 即可，协议完全兼容。
- MCP 官方 registry 的 **1864+ 服务器**全部可用。

**配置示例**（`.waycoder/mcp_servers.json`）：

```json
[
  { "name": "filesystem", "command": "npx", "args": ["-y", "@modelcontextprotocol/server-filesystem", "."] },
  { "name": "github", "transport": "http", "url": "https://api.example.com/mcp", "headers": { "Authorization": "Bearer ${GITHUB_TOKEN}" } },
  { "name": "legacy", "transport": "sse", "url": "https://api.example.com/sse", "headers": { "Authorization": "Bearer ${TOKEN}" } }
]
```

**唯一前提是 transport 覆盖全**，WayCoder 支持三种：

| transport | 说明 | 对应服务器类型 |
|---|---|---|
| `stdio`（默认） | 子进程 stdin/stdout JSON-RPC | `npx`/`uvx`/本地二进制 |
| `http` | Streamable HTTP（POST + SSE 响应流） | 新版 HTTP 端点 |
| `sse` | legacy HTTP+SSE 双端点（GET /sse + POST /message） | 旧版 SSE 端点 |

> 字段对齐：`command`/`args`/`url`/`headers`/`env`，`${VAR}` 环境变量引用自动展开。竞品配置里的字段名基本一致，多数可直接搬。

---

## 2. LSP —— server 生态完全共用（客户端各写各的）

- **可共用的不是竞品的 LSP 代码**，而是它们指向的 **language server**：`gopls` / `clangd` / `rust-analyzer` / `typescript-language-server`……这些是语言官方工具，任何编程 agent 都用同一批。
- WayCoder 的 `LspTool`（`lsp` 工具，go-to-def / references / hover / symbols）是**自研的 LSP 客户端**——因为 AOT 禁止反射、要走自己的异步模型——但接的 server 和竞品完全一样。
- 竞品配置里写的 server 命令/参数，直接搬进 WayCoder 的 LSP 配置即可。

---

## 3. SKILL —— 高度共用（格式标准，微调即可）

`SKILL.md`（YAML frontmatter：`name` + `description` + markdown 正文）是 Anthropic 引入的标准，WayCoder 的 `SkillsManager` 采用「标准 SKILL.md 格式」。

- Claude Code / Crush / Cline 的 skill 目录 → 拷进 WayCoder 的 skills 路径即可复用。
- **差异点**：frontmatter 里的进阶字段（`allowed-tools`、`version`、`license` 等）各家略有不同。WayCoder 解析时**容错**（只认 `name`/`description`，多余字段忽略）即可无缝吃下竞品的 skill。

> WayCoder 内建技能在 `WayCoder/Skills/builtin/`，用户自定义技能放项目 `.waycoder/skills/`。

---

## 4. 插件 —— 外壳不可共用，内部资源可「拆包」

"插件"是各家私有概念，API 不互通：

| 竞品插件 | 为何不能直接共用 |
|---|---|
| Cursor 扩展（`.vsix`） | 依赖 VS Code API，终端 TUI 用不了 |
| Claude Code plugins | 依赖 Claude Code 的 hooks/subagents 运行时 |
| Cline / Aider 插件体系 | 各自私有封装 |

**但插件的底层资源可拆**：大多数插件内部封装的正是 MCP 服务器、`SKILL.md`、slash command 的 `.md`、hooks 脚本。把这些拆出来，走上面第 1/3 节的路就能复用。**不可复用的只是插件的注册外壳和 UI 集成。**

---

## 5. 其他可共用的资源

| 资源 | 竞品来源 | WayCoder 落点 |
|---|---|---|
| Slash commands | Claude Code 的 `.claude/commands/*.md`（纯 markdown + frontmatter） | `.waycoder/commands/*.md` |
| Prompt/规则文件 | `.cursorrules`、Crush 规则文件 | CLAUDE.md / ProjectContext |
| Models + API keys | OpenAI 兼容接口通用 | `.env` 直接复用 |

---

## 复用优先级建议

如果要对接竞品生态，性价比从高到低：

1. **MCP**（最大生态、零改造、立即生效）—— WayCoder 已支持三种 transport，侧栏面板（`Ctrl+B`）的「🔌 MCP」区可直接看连接状态与已发现工具。
2. **SKILL**（改动最小，拷目录即可，只需容错 frontmatter）。
3. **Slash commands**（纯 markdown，搬目录即可）。
4. **LSP server**（server 复用零成本，但 WayCoder 客户端已自研，无需对接竞品客户端）。
5. **插件**（不要试图对接外壳，只拆内部 MCP/SKILL 资源）。
