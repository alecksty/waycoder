# 移动端编辑器：已实现 / 待实现

写于 v0.96.218（2026-09-18），把「手机编辑器」这条线上的**现状**与**下一步**摊开，
方便以后接着做。每条都尽量给出**可以下手的位置**（文件 + 函数），而不是只写一个愿望。

---

## 一、现在已经有的

不是从零开始的 —— 下面这些是**已经在真机上跑通**的，新功能应当尽量复用它，
而不是另起一套（本仓库的头号坑就是「同一规则两处实现」）。

| 能力 | 落地位置 |
|---|---|
| 自绘虚拟化编辑器（大文件不卡） | `WayCoder.Maui/Controls/CodeCanvasView.cs` |
| 语法高亮（含 VML 那 22 门语言） | `WayCoder/UI/TUI/Edit/Syntax.cs` 的 `ForFile` / `Tokenize` |
| 编辑（IME / 选区 / 复制粘贴 / 撤销重做） | `EditorPage.xaml.cs` 的 `OnLineEditorTextChanged` / `CommitEditingLine` / `DeleteSelectionCore` |
| 行首退格跨行合并（Android） | `Platforms/Android/BackspaceAwareEditText.cs` + `EditorEntryHandler.cs` |
| **不依赖输入法的退格键**（浮条上的 ⌫） | `EditorPage.xaml.cs` 的 `AssistBackspaceAsync` |
| 查找 / 大纲 / 跳到行 / Markdown 预览 | `EditorPage.xaml.cs` |
| 编译 + 运行 + 底部面板（错误列表 / 输出 / stdin / 停止） | `RunCurrentFileAsync` / `CompileInEditorAsync` / `RunInEditorAsync` |
| 诊断数据源（气泡 / 波浪线 / 错误列表 / 状态栏计数，四处同源） | `WayCoder/UI/TUI/Edit/DiagnosticManager.cs` |
| 错误文本 → 结构化诊断 | `WayCoder/UI/Shared/VmlDiagnostics.cs`（两端共用） |
| 诊断气泡（绑死代码坐标、随缩放滚动、可关） | `EditorPage.xaml.cs` 的 `RebuildBubbles` / `RelayoutBubbles` |
| 浮动辅助输入条 | `EditorPage.xaml.cs` 的 `ToggleAssistBar` / `ShowAssistPopup` / `AssistInsertAsync` |
| 全角→半角（避开字符串与注释） | `WayCoder/Infra/FullWidthText.cs` + `Syntax.ProtectedSpans` |
| 编辑器设置（字号 / tab / 编码 / 换行 / 全角 / HUD） | `WayCoder.Maui/Services/MauiEditorStore.cs` |

**一句话概括现状**：「跑起来 + 报错」这条链（最难的一段）通了；
「写代码时的辅助」那半边基本是空的。

## 二、待实现（按建议顺序）

顺序的依据是**复用成本**：前三个都能直接接上今天已经搭好的 `DiagnosticManager` 与 `Syntax`。

### 1. 实时诊断（打字时就报错）

**现状**：气泡**只在点运行之后**出现。`DiagnosticManager` 的写入方只有编译器那一路。
**为什么值得做**：这是「编辑器」与「能跑的查看器」分界线上最明显的一件。

**下手点**：
- 数据入口早就留好了 —— `DiagnosticManager.Inject(filePath, list)` 就是为「从外部灌诊断」加的
  （气泡就是这么来的）。实时诊断只是**换个写入方**，渲染侧一行都不用改。
- 触发：`EditorPage` 里给 `OnLineEditorTextChanged` 挂一个**防抖**（300~500ms）任务，
  后台跑一次「只编译不链接」拿到诊断，再 `Inject` + `RebuildBubbles()`。
- **难点**：手机上前端编译要一分多钟 —— 全量重编不可能。可行的折中：
  ① 只对**小文件**开；② 只在**停止输入**后跑；③ 先只做「保存时诊断」。
  ⚠ 现有 `ClearDiagnosticsOnEdit()` 是「用户一动手就把上一轮诊断清掉」——
  接了实时诊断之后要考虑要不要保留它，否则两边会互相打架。

### 2. 自动补全

**现状**：辅助输入条是**手点的字符板**，不是上下文感知的补全 —— 没有成员提示、没有参数提示。

**下手点**：
- 候选来源已经有了：`Syntax.ForFile(path).Keywords`（关键字）；同文件的标识符可以扫
  `EditableLines` 现扫现用（不需要索引）。
- 插入路径也有了：`AssistInsertAsync(string)` —— 它会把文本插到光标处，
  且没在编辑时先落到光标行。补全的结果直接喂它即可。
- 弹出的 UI 可以**直接借辅助输入条的弹表**（`ShowAssistPopup` + `FlexLayout`），
  不必新写一套浮层。
- **难点**：触发时机（`LineEditor.TextChanged` 里取光标前那个词）+ 候选排序 + 不遮挡光标。
  ⚠ 别在 `TextChanged` 回调栈里回写 `LineEditor.Text`（会打断 IME 组合态，见 `EditorPage` 里那条硬约束注释）。

### 3. 转到定义 / 查引用

**现状**：桌面有 `LspTool`（`WayCoder/Tools/LspTool.cs`），移动端是桩
（`WayCoder.Maui/CoreStubs.cs`）。编辑器里没有任何跳转入口。

**下手点**：
- 长按菜单里加「转到定义」（现在长按是选词）。
- 真正做事的是语言服务器；VML 那 22 门前端**只有编译器、没有 LSP**，
  所以这条路要么接真 LSP（手机上跑不起来 / 要额外二进制），要么退化成
  **前端编译器自己的符号表**（`VMLPrepares/*/CodeGenerator*.cs` 里都有 `symbolTable`，
  但都是 `private`，且不在一个统一的接口后面）。
- **难点**：这是一条**需要新增基础设施**的路，不是接现成设施。排在补全之后做更划算。

### 4. 多文件：标签页 / 分屏，并与「文件」页打通

**现状**：编辑器是**单文件**的（`EditorPage` 一次只载一份 `_doc`）；
文件树在 `FilesPage`，两边靠 `editor?path=` 路由参数连接。

**下手点**：`EditorPage.LoadAsync(relPath)` 是唯一的加载入口 ——
多文件要在它外面加一层「打开过的文件列表 + 当前索引」，并把 `_doc/_editable/_history/_modified`
这一组状态**按文件**存起来（现在全是单份字段）。

### 5. 编辑器内的版本控制

**现状**：有独立的「同步」页；编辑器里没有 diff / 暂存 / 提交入口。
**下手点**：`WayCoder/Git/GitRunner.cs` 是所有 git 调用的唯一实现（桌面侧），移动端要能跑得确认它没被排除。
展示可以复用已有的 diff 渲染（`UI/Shared/UnifiedDiff.cs` 是跨端共享的纯逻辑）。

### 6. 调试（断点 / 单步 / 变量）

**现状**：只有运行。
**下手点**：VML 运行时（`third_party/vml/VMLRuntime`）是自家 VM，**理论上可以加断点**，
但那是 VM 与宿主协议层面的事，成本远高于上面几件。建议放到最后。

### 7. 编辑细节（成本低、体感明显）

这几件都不需要新基础设施，属于「顺手就该有」：

- **括号匹配高亮**：`CodeCanvasView.DrawCaret` 那一层已经知道光标在哪一列，加一次括号配对扫描即可。
- **自动缩进**：`OnLineEditorCompleted`（回车那条路）现在插的是空行，可以继承上一行缩进。
- **自动配对括号/引号**：插入路径集中在 `AssistInsertAsync` 与 `OnLineEditorTextChanged`。
  ⚠ **全角转半角**（`FullWidthText`）要在它之前或之后有个确定顺序，别两处都改一次。
- **代码折叠**：`CodeCanvasView` 的虚拟滚动是按行索引做的，折叠要引入「行号 → 显示行号」的映射，
  牵动面较大（渲染、光标、命中测试、选区都走这套映射）。
- **minimap**：同上，且手机上屏幕本来就小，收益存疑。

## 三、现行实现里的已知边界（不是「没做」，是「做了但有前提」）

这些是**有意留下的**，写在这里免得以后被当成 bug 重新发现一遍：

| 边界 | 说明 | 位置 |
|---|---|---|
| 跨行字符串/块注释里的标点**会**被转全角 | `Syntax.Tokenize` 是**逐行**的，判不出跨行 `/* */` 与 Python 三引号。已有保守兜底（受保护区间占半行以上就整行不转） | `Syntax.ProtectedSpans` |
| 关键字匹配**区分大小写** | `Keywords.Contains(word)` 是 ordinal 比较。词表按各语言书写惯例存（BASIC/Forth 大写、Fortran 小写），另一种大小写不命中 | `Syntax.Tokenize` |
| 气泡只认三类错误格式 | 中文 `在第N行M列` / GCC `file:line:col:` / 英文 `at line N`。**再来一种新格式就解析不出位置** —— 那条照旧进「错误列表」（文字行），但**画布上不画气泡**（用户定的：指不到行的、以及行号越界的，都不画）—— 遇到时按同样方式往 `VmlDiagnostics.Parse` 里加一条 | `VmlDiagnostics.cs` |
| 气泡之间「不重叠」优先于「紧贴自己那一行」 | 两个错误行挨得很近时，后者会被往下推。位置仍只由代码坐标决定（滚动不跳） | `RelayoutBubbles` |
| 编译期间**锁编辑、但保留滚动** | 避免结果回来时行号已经偏了 | `CompileInEditorAsync` |
| 气泡是**代码层的一部分**，不是浮层 | 不翻面、不为视口避让、被工具栏/面板盖住就盖住 —— 这是用户明确定的口径 | `RelayoutBubbles` 的方法注释 |
| `.vml` / `.vmb` / 大文件只读**不在编辑器里编译** | 它们本就是汇编/字节码，直接交给 `MauiVml.Run` 按扩展名派发 | `RunCurrentFileAsync` |
| **部分输入法的退格永远到不了应用** | 用户实测换了个输入法就好了：**有些输入法的退格只作用于它自己的联想词库，从不回调编辑框**（现象是「候选区随退格变、文本一个字不动」）。那种情况下 `InputConnection` 这条路**根本够不着** —— 它不调用我们，拦也没得拦。所以浮条上必须有一个**应用自己的 ⌫**（`AssistBackspaceAsync`，不经过输入法）。平台那条路留着，它管的是另一批输入法 | `BackspaceAwareEditText.cs` + `AssistBackspaceAsync` |

## 四、还没在真机上验过的两条

**没亲眼见到就不算验过**，这两条我试了两次都没抓到中间态（编译都在 4 秒内结束）：

1. **编译进度只在底部面板里**（去掉全屏遮罩之后）
2. **编译期间点代码行不进编辑态**（锁编辑生效）

要验它们，需要一个**编译真的会跑上一分钟**的用例。手机上 C 前端编一份 3 万多条指令的
程序实测一分多钟 —— `examples/c/tetris.c` 是一分钟量级，但那次实测是在**冷启动**下
（标准库要先解压）；标准库解压过一次之后会快很多。
**验的时候注意**：别用 `adb shell input keyevent 4` 做退出导航 —— 会把 App 退到后台，
后续的盲点击会落到别的应用上（这事真发生过）。

## 五、几条与实现无关、但下次会省事的经验

- **真机才暴露的那类问题**：气泡的箭头用「旋转 45° 的方块」想做三角，实际露出来是**菱形**
  （尾巴是相邻的独立元素，没被裁）；`VerticalStackLayout` 会把子元素**横向拉伸**，
  10×10 的三角被拉成一条看不见的薄边（改用 `AbsoluteLayout` 精确定位）；
  MAUI 的 `Grid` 会把**没填满单元格的子元素居中**，算好的 `TranslationX` 会叠在居中偏移上
  （`HorizontalOptions=Start` 不能省 —— `SelectionBar` 当年就是为这个写的）。
- **构建**：Windows 上直接 `dotnet publish` + 显式签名参数（`build-apk.sh` 是 Mac 专用）。
  **`TaskStop` 中断构建会留下孤儿 `dotnet`/MSBuild 进程锁住 `obj/`**，
  症状是 `XAGJS7000` + Mono.Cecil 读文件失败 —— 清法见那次会话（按启动时间筛出孤儿再杀）。
  另外**别同时起两个构建**写同一个 `obj/`。
- **浮动条「拖动乱晃」的真身是 MAUI 的 Pan 会在拖动中途自己结束一次手势**（不是像素/DIP 换算 ——
  那个是 `PixelTranslation → context.FromPixels`，本来就是 DIP）。看过 MAUI 源码才明白：
  `InnerGestureListener.OnFling` 会调 `EndScrolling()`，于是快速拖动时我们收到一个 `Completed`；
  手指还在屏幕上，下一个 MOVE 又开启新一轮、发一个 `Started` + 一份新的累计值，
  而那份累计值的**起点始终是最初那次 ACTION_DOWN**（`SetStartingPosition(e1)` 里 e1 一直是 down 事件）
  ⇒ 累计值从小数**跳回**「离按下点有多远」；偏偏 `Started` 里又把锚点重设成当前位置，
  两者叠加 = 每次重启都朝手指方向**再窜一整个全程**。**拖得越快越晃**正是它的指纹。
  解法是**改成逐次增量**（`ApplyAssistPan`：每轮第一个事件只取基线、不产生位移，之后按差值走）——
  这样对「累计值何时归零」这件事彻底免疫。**教训**：包在平台手势之上的浮层，
  别用「起点 + 累计位移」这种依赖平台语义的写法；用增量，天然只依赖「两次事件的差」。
- **`adb` 中文输入**：`adb shell input text` 发不了非 ASCII，全角相关的功能只能靠人手动验。
