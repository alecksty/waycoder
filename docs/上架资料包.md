## 五、App 隐私问卷（口径：不收集）

⚠ **口径已定：不收集**。理由：本 App 把内容发给**用户自己配置**的 LLM 端点
（用户自己的 key、自己的服务器），开发者**既不接触也不留存**这些内容，数据流向完全由用户
指定 ⇒ 按苹果口径不计入"开发者收集"。这也是绝大多数「自带 API Key」客户端的通行做法。

| 题目 | 答 |
|---|---|
| 是否收集数据 | **否** |
| 是否用于追踪 | **否**（无 IDFA、不打 ATT 授权弹窗） |
| 是否使用第三方 SDK 收集 | 否（MAUI 本身不带广告/分析 SDK） |
| 是否提供账号体系 | 否（App 内没有账号，能省掉一大串追问） |

答「否」之后，后面那一长串「收集哪一类 / 用途 / 是否与身份关联 / 保留多久」都不再出现。

⚠ **三处必须同时是"不收集"**，缺一处就是自相矛盾的申报：

1. **本节** —— App Store Connect 的问卷按"否"填；
2. **随包隐私清单** —— `WayCoder.Maui/Platforms/iOS/Resources/PrivacyInfo.xcprivacy` 的
   `NSPrivacyCollectedDataTypes`（现为**空数组** = 一种也不收集，是合法且明确的写法）；
3. **隐私政策正文** —— `docs/PRIVACY.md` 与 App 内那一份（设置 → 关于 → 使用说明与隐私）。

⚠ 将来若接了**我们自己的**中转 / 统计 / 崩溃上报（数据落到我们这边），**三处都要同步改**
—— 那就不再是"不收集"了。

## 八、功能门 + 内购怎么落

### 8.1 功能门（分界已定，**只有两处**必须收紧）

两处分别落在两个文件里：

| 门 | 位置 | 免费版怎么拦 |
|---|---|---|
| **语言** | `MauiVml.cs:655` 拿到 `compiler`、`:659` 得到 `lang` 之后 | `lang != "c"` 且未解锁 ⇒ 直接 `Fail` +
一句「全能版可解锁这门语言」。VML 汇编走的是另一条路（`RunAssembly`），不受此门影响 |
| **优化器** | `MauiCompileStore.OptimizationLevel` 的 getter（`:83`） | 未解锁 ⇒ 直接返回 `OptimizationPolicy.Off`（0）。
**不在编译处钳** —— 设置里压根不显示这一项，编译处只消费 getter 的值 |

⚠ **优化器门做的是「不显示 + 不启用」，不是「显示了但暗地里钳住」**。
理由是 `MauiCompileStore` 的状态栏会显示「优化 O2」（`:160`）：只钳执行不钳显示，界面就当面撒谎了。
把钳制收在 **getter 一处**，执行与显示**同源**，这类不一致就不可能发生 —— 这也正是本仓一贯的写法。

语言门同理：免费版**在语言入口/文件页就把非 C 语言打上锁**，而不是让用户点下去才报错。
两个门的判据都放 `WayCoder/UI/Shared/FreeTierPolicy.cs`（**纯逻辑，放 Shared 才能被桌面自测覆盖**）：
`IsLanguageFree(name)` 与 `EffectiveOptimizationLevel(isFull, level)`。

### 8.2 内购（StoreKit / Google Play Billing）—— **已实现（v0.96.577）**

产品：**只有一个**非消耗型 `com.tanso.dolaima.full`（显示名「全能版」），美国区 **$9.99**。
先按这个价跑、随时可改（已购用户不受改价影响）。**不做第二个付费档** —— 理由见第十一节。

落点（这一版之前是"一行内购代码都没有"，现已全部落地）：

| 层 | 文件 | 说明 |
|---|---|---|
| 状态 | `WayCoder.Maui/Services/EntitlementStore.cs` | 解锁状态唯一事实源：`IsFull` / `Set` / `Changed` + 文案。**唯一写入口是 `Iap`**，UI 不许直接写 |
| 传输 | `WayCoder.Maui/Services/Iap.cs` | 平台层，`#if` 三分支。iOS/MacCatalyst 用 SDK 自带的 **StoreKit**；Android 用 **Play Billing 的 AAR 绑定**；其余平台显式"不支持" |
| 口径 | `WayCoder/UI/Shared/FreeTierPolicy.cs` | 分界 + **产品 ID**（`FullEditionProductId`）。放 `UI/Shared` 才进得了桌面自测，字面量才有判据 |
| 门 | `MauiVml.Run` / `MauiCompileStore.OptimizationLevel` | 语言门 / 优化器门，各收一处 |
| UI | 设置页「全能版」卡片 + 二级页；文件页菜单锁 | 购买 / **恢复购买** |

⚠ **两端各写各的**，不引 `Plugin.InAppBilling` 那类跨端抽象层：StoreKit 绑定随 SDK 就有
（零依赖、天然 AOT 安全），Android 用纯 AAR 绑定（无反射）。理由与取舍见 `Iap.cs` 的类注释。

⚠ **Android 的 `acknowledge` 不能漏**：买完不应答，Google **三天后自动退款** ——
表现是"用户买了、三天后钱退回去、功能也没了"。这与 App Store 是最大的语义差别。

⚠ **「恢复购买」是硬要求**：非消耗型必须能跨设备/重装恢复，审核会实际点它。
三件事必须分清：**恢复成功但没买到过**（⇒ 资格写 false）、**恢复本身失败**（⇒ 状态一个字不动）、
**恢复到了**（⇒ true）。写成"没到就 false"会让断网用户一按恢复就丢掉已买的资格。

⚠ **本版只做到「编译验证」**。真实交易要真机 + 商店后台，见下面 8.3。

### 8.3 内购的真机验收（上架前必做，开发机上做不了）

`WayCoder.Maui/Services/Iap.cs` 的两个平台分支**只编译验证过** ——
StoreKit 与 Play Billing 的真实交易需要真机 + 商店后台把产品建出来。

**逐条操作步骤在 [上架逐屏操作](上架逐屏操作.md) §七**（前置准备 + 十条判据 + 每条看什么）。
这里只记一件必须知道的事：

⚠ **真机上验收内购，装不了上架包**。`build-ios-appstore.sh` 出的是 **App Store 类型 .ipa**，
它只能经 Transporter / TestFlight 分发；内购沙箱验收要另出一个**开发签名**包
（VS 配对 Mac 后选真机部署，或 `dotnet build -f net10.0-ios27.0 -t:Run -p:_DeviceName=:v2:udid=<UDID>`）。

#### 决策记录：第 10 条（退款后收敛）为什么改了判据

原判据是"沙箱里退款后**重开 App** ⇒ 资格收敛"。**按现在的代码做不到**，原因是两条叠加：

1. 解锁状态在本地是**缓存**的（`EntitlementStore` → `Preferences`），退款不会自动清掉它；
2. 设置页 `SettingsGroupPage.xaml.cs:257` 是
   `FullRestoreBtn.IsEnabled = supported && !full` —— **已解锁时「恢复购买」按钮是禁用的**，
   而唯一的收敛路径（`Iap.RestoreAsync` 走到 `RestoreCompletedTransactionsFinished` 才敢写 false）
   在界面上**点不到**。iOS 的 StoreKit 也不会把退款当作交易更新推给应用。

⇒ **判据改成：收敛通过"删掉重装 + 点恢复购买"发生**，不是"重开 App 自动收敛"。

**为什么本轮不改代码**：让"不重装也能收敛"是产品行为变更（解锁态也允许刷新购买状态、
或启动时静默恢复一次），影响面比这次上架收尾大。记在这里，免得下次又当新问题绕回来。

## 十一、为什么是两档而不是三档（决策记录）

原本考虑过「免费 / Pro（4 种语言）/ Max（全功能）」。否掉的理由记在这里，免得以后又绕回来：

1. **非消耗型内购没有升级通道**。买了 Pro 想要 Max，只能**再付一次全价** —— 苹果没有 Pro→Max 的
   原生升级。要修就得再加一个「补差价升级」产品，产品数从 1 变成 3。
2. **「4 种语言」这条线切不干净**：选哪 4 门都会得罪另一半人，而且用户会当场算「再加几美元就给 22 门」，
   中间档必然被 Max 档吃掉。
3. **三档会拖慢决策**：商店页的购买决定是几秒内做完的，三个档位会让人退出去想「我到底要哪个」。

真想要「便宜点的入门」，正确做法是**把买断价降到 $6.99**，而不是加一个 4 语言档 —— 效果相近，
不用付上面三条代价。

另外两条当时也想清楚了：

- **免费档给 C 而不是 Python**，是刻意的：C 分量足（一门真语言 + 完整工具链），
  但不足以让人「不买也能干活」；想用 Python 跑脚本的人，正是要转化的那批。
- **不拿 AI 智能体当档位**：它花的是用户自己的 API Key，对你零成本，砍它等于砍招牌功能，
  还会让审核员觉得这 App 是个空壳（见第七节那条「必须给审核员一个可用 Key」）。
