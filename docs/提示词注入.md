# 提示词注入点清单

本文档列出 WayCoder 代码中所有**注入到 LLM 对话上下文**的硬编码提示词，以及各自的触发时机与注入角色。

> 范围说明：只统计进入 LLM 请求（`role=system` / `role=user` / `role=tool` 消息）的文本。
> 终端/Web 界面显示的系统消息（`screen.AddMessage`）不属于 LLM 注入，不在本文档内。

**注入的三种角色**
| 角色 | 含义 |
|---|---|
| `system` | 系统提示词，指导模型行为 |
| `user` | 追加给模型的一轮用户指令（nudge / 继续提示） |
| `tool` | 工具执行结果，附加进对话上下文（如自动 lint/测试反馈、合成错误结果） |

---

## 1. 每轮请求固定注入（`role=system`）

每次调用 LLM 前，`Agent.FullMessages()`（`Agent/Agent.cs:180-213`）组装系统提示。

### 1.1 主系统提示 — `SystemPrompt.Generate()` / `GenerateTiny()` / `GenerateEconomy()`

- **位置**：`Agent/SystemPrompt.cs:24-392`
- **触发**：每轮 LLM 请求（`Agent.FullMessages()` 第一条消息）
- **模式选择**：
  - `--tiny`（TinyMode）→ `GenerateTiny()`（`SystemPrompt.cs:398`，极简 8 条规则）
  - `--economy on`（EconomyMode）→ `GenerateEconomy()`（`SystemPrompt.cs:432`，精简规则、保留工具/项目上下文）
  - 默认 → `Generate()`（完整 16 条 critical_rules + 10 阶段流水线 + 编辑/错误/测试等区块）

**完整版动态填充项**（占位符 → 内容）：

| 占位符 | 填充内容 | 来源 |
|---|---|---|
| `__CWD__` | 工作目录 | `Directory.GetCurrentDirectory()` |
| `__OS__` | 操作系统 + 架构 | `RuntimeInformation` |
| `__DOTNET__` | .NET 版本 | `Environment.Version` |
| `__PROJECT_CTX__` | 项目检测摘要（语言/构建工具/框架） | `ProjectContext.DetectProject()` |
| `__GIT_STATUS__` | Git 状态（分支/工作区变更/最近 3 条提交） | `GenerateGitStatus()` `SystemPrompt.cs:541` |
| `__INSTRUCTIONS__` | CLAUDE.md 指令 | `ProjectContext.LoadInstructions()` |
| `__MEMORY__` | 项目记忆（按相关性匹配 + 跨会话检索） | `StructuredMemory.GetRelevantContext` + `MemoryRetrieval.GetRelevant`，`SystemPrompt.cs:44-89` |
| `__SKILLS__` | 可用技能列表（`<available_skills>` XML） | `SkillsManager.GetSkillsXml()` |
| `__REPO_MAP__` | 仓库地图（文件结构） | `RepoMapGenerator.Generate()` |
| `__TOOL_LIST__` | 全部工具名 + 描述 | 工具注册表 |
| `__WORKFLOW_CONTENT__` | 工作流文本 | `s_standardWorkflow` / `s_fastModeWorkflow` |
| `__RULE_READ_BEFORE_WRITE__` | 规则 1「先读后改」 | `s_standardRule1` / `s_fastModeRule1` |

**Tiny/Economy 版**只填环境 + 工具 + 规则，不注入 RepoMap / 记忆 / Git 状态 / 技能 / 流水线。

### 1.2 模式提示前置 — `WorkModeManager.GetModePrompt()`

- **位置**：`Agent/WorkModeManager.cs:115-145`
- **触发**：`Agent.FullMessages()` 在系统提示前拼接（`Agent/Agent.cs:183-186`）
- **内容**（按 `WorkMode`）：
  - `Plan` → 「🧠 计划模式」只分析不修改、禁用修改性工具
  - `Review` → 「🔍 审查模式」只读审查
  - `Auto` → 「🤖 自动模式」工具按风险级别放行
  - `Build` → 不附加（标准提示）

### 1.3 快速模式工作流替换 — `FastModeWorkflow` / `FastModeRule1`

- **位置**：`Agent/SystemPrompt.cs:505-535`
- **触发**：用户消息命中 `DetectFastMode()` 关键词（`SystemPrompt.cs:642`：不要读文件 / 不要ls / 跳过探索 / don't read / just write 等）→ `_fastMode=true`（`Agent/Agent.cs:261-265`）
- **动作**：把标准 workflow 和规则 1 替换为「读旧写新、直接执行」版本（`Agent/Agent.cs:189-194`）

## 2. 主循环动态注入（`role=user` / `role=tool`）

在主循环（`ChatAsyncCore`，`Agent/Agent.cs:288-551`）每轮检查条件，命中即追加消息。

### 2.1 纯推理不行动 — 3 级渐进

- **位置**：`Agent/Agent.cs:374-387`
- **触发**：`reasoningLen > 300` 且 `toolCallCount == 0` 且 `contentLen < 80`（模型大量输出推理但无实际内容）
- **注入**：`reasoning 已消耗 N 字符但没有工具调用，请立即调用工具…` → 第 2 次升级 → 第 3+ 次严重警告

### 2.2 只分析不动手 — 3 级渐进

- **位置**：`Agent/Agent.cs:389-403`
- **触发**：首轮 `toolCallCount == 0` 且 `contentLen > 100`（只输出分析不调用工具）
- **注入**：`请立即用工具执行上述计划…` → 2 次 → 3+ 次严重警告

### 2.3 口述代码 — 3 级渐进

- **位置**：`Agent/Agent.cs:405-419`
- **触发**：`contentLen > 300` 且含代码特征（`` ``` `` / `class ` / `public ` / `def ` 等）且无 `✅`（模型用文字贴代码而非写文件）
- **注入**：`不要用文字输出代码，立即调用 write_file…` → 2 次 → 3+ 次严重警告

### 2.4 任务中无工具调用 — 3 级渐进

- **位置**：`Agent/Agent.cs:424-437`
- **触发**：`toolCallCount > 0` 且无完成信号（无 `✅` / `任务完成` / `已完成` / `全部完成`）
- **注入**：`本轮没有调用工具，任务尚未完成，请继续…` → 2 次 → 3+ 次严重警告

### 2.5 计划批准后继续

- **位置**：`Agent/Agent.cs:361-363`
- **触发**：Plan 模式审批框被用户批准
- **注入**：`✅ 计划已获批准。现在切换到建造模式，按上述计划逐步执行…`

### 2.6 SHA256 反循环 — 3 级渐进

- **位置**：`Agent/Agent.Loop.cs:299-308`
- **触发**：per-tool 指纹（工具名+参数+输出前 2000 字符）哈希在滑动窗口内出现 ≥5 次（`PerToolLoopThreshold`）
- **注入**：
  1. `检测到重复的工具调用模式。请换一种不同的方法或工具…`
  2. `你仍在重复相同的操作模式。请停下来，重新评估问题，尝试完全不同的策略…`
  3. `严重警告：你已经多次重复相同的无效操作。立即停止当前方法，从第一步重新开始…`

### 2.7 上下文压缩后继续 — `InjectContinuePrompt`

- **位置**：`Agent/Agent.cs:630-652`
- **触发**：上下文自动压缩后且 Agent 仍在执行任务中（`Agent/Agent.cs:498-502`）；或达到轮数上限自动续跑（`Agent/Agent.cs:538`）
- **注入**：`{原因}。原始用户请求是：{前 200 字符}…请从中断处继续…` + 已创建/修改文件清单

### 2.8 Stop Hook 注入

- **位置**：`Agent/Agent.cs:508-515`
- **触发**：每轮完成后 `HooksManager.RunStopAsync()`，hook 返回 `SystemMessage` 内容时
- **注入**：hook 返回的文本作为 `user` 消息

### 2.9 孤儿工具调用合成错误结果（`role=tool`）

- **位置**：`Agent/Agent.Loop.cs:86-92`
- **触发**：存在 tool-call 但无对应 tool-result（Agent 中断 / 会话恢复 / 输出截断）
- **注入**：`[工具执行被中断] 工具 "{name}" 的调用未能完成执行。可能原因：Agent 被中断、网络问题…请重试或使用其他方法…`

### 2.10 FileTracker 文件变更警告（`role=tool`）

- **位置**：`Infra/FileTracker.cs:194-208`，注入于 `Agent/Agent.cs:465-476`
- **触发**：bash 等外部命令修改了 Agent 已读取的文件（SHA256 变更检测）
- **注入**：`⚠️ 文件变更警告：以下已读取的文件被外部修改：` + 文件列表（前 10 个）

### 2.11 预算上限终止

- **位置**：`Agent/Agent.cs:303-307`
- **触发**：`EstimatedCost >= MaxBudgetUsd`
- **行为**：返回终止文本（不注入，直接结束本轮）

## 3. 工具结果反馈追加（`role=tool`）

工具执行完成后，把额外检查结果**追加到工具结果文本**，随下轮一起进入上下文。

### 3.1 Lint 自动检查 — `AppendLintFeedbackAsync`

- **位置**：`Agent/Agent.Feedback.cs:25-60`
- **触发**：`write_file` / `edit_file` 后自动跑 lint（`LintTool`），且发现 `✅`/`⚠` 之外的问题
- **追加**：`--- Lint 自动检查 ({lang}) ---\n{lint 结果}`（超 1500 字符截断）

### 3.2 测试自动检查 — `AppendTestFeedbackAsync`

- **位置**：`Agent/Agent.Feedback.cs:69-151`
- **触发**：`write_file` / `edit_file` 修改源码文件（`.cs/.py/.ts/…`）后自动跑项目测试，且测试失败（防抖 60s）
- **追加**：`--- 🔴 自动测试失败 (exit=N) ---\n{输出}\n[请修复代码使测试通过]`（超 2000 字符截断）

## 4. 子智能体注入

### 4.1 子智能体任务提示 — `RunSubAgentAsync`

- **位置**：`Tools/AgentTool.cs:151-195`
- **触发**：每次通过 `agent` 工具启动子智能体
- **内容**（作为子智能体的首条 `user` 消息）：
  - 父上下文摘要 `BuildParentContext`（最近几轮对话，`AgentTool.cs:214+`）
  - `SystemPrompt.SubAgentDiscipline`（`Agent/SystemPrompt.cs:17-22`，4 条纪律：不建 scratch/csproj、自测到通过、精简回报、不越界改模块）
  - 子任务文本 + 深度注记（`（当前为第 N 层子智能体，最大深度 M）`）
- 子智能体系统提示：由它自己的 `Agent.FullMessages()` 生成（同 §1.1），但模型用小模型 + 深度受限工具集

## 5. 专用一次性任务

### 5.1 Git commit 消息 — `GenerateCommitMsgAsync`

- **位置**：`Agent/Agent.Commit.cs:93-125`
- **触发**：自动 git commit（`--autocommit` / `/autocommit`）或用户触发 commit
- **系统提示**：`You are a git commit message generator. Output a single line, English, conventional-commit style… <70 chars…`（英文）
- **失败重试**：`Your previous output was invalid. Strict rules: …`（`Agent.Commit.cs:110`）
- **兜底**：仍不合格 → `chore: update {首个文件}`

### 5.2 Architect 架构师提示 — `GenerateArchitectPrompt`

- **位置**：`Agent/SystemPrompt.cs:671-714`，使用于 `Agent/Agent.Commit.cs:220`
- **触发**：Architect 模式（`/architect on`）+ 大模型 → 先用大模型纯分析出计划
- **内容**：`你是 WayCoder 的 Architect（架构师）…不写代码…输出格式：分析/执行计划/预估` + 项目上下文 + RepoMap

### 5.3 Architect 计划注入执行

- **位置**：`Agent/Agent.cs:280-285`
- **触发**：Architect 计划生成成功 → 作为 `system` 消息注入，切换小模型执行
- **注入**：`## 执行计划\n\n以下是 Architect 的分析和执行计划，请按步骤逐一执行：\n\n{plan}`

### 5.4 对话压缩摘要 — `GetSummaryAsync`

- **位置**：`Agent/ContextManager.cs:436-482`
- **触发**：上下文压缩三层（50% 裁剪 / 70% LLM 摘要 / 90% 硬折叠）任一触发，用 LLM 生成摘要
- **系统提示**：`你是一个对话压缩器。将以下对话压缩为结构化摘要。必须保留：文件路径/API 签名/类结构/架构决策/错误修复/未完成任务/命名空间…丢弃：命令输出/完整代码/重复对话…`（`ContextManager.cs:449-460`）
- 回退：LLM 摘要失败 → `ExtractKeyInfo` 提取文件路径和错误 + 任务进度注入

## 6. 多模态注入

### 6.1 图片查看消息
